## 🟢 工具用法（①⑤ 快線）

- **Claude Code 12 個藏起來的 settings.json 開關（一行一設定、全非 code）** — 🏢 直接省成本＋防雷：`opusplan`（Opus 規劃、切執行自動降 Sonnet）、`/effort` 陷阱（實測 max 以下品質幾乎不動、正確率零變化，多花的 token 只買到「反覆驗證與加註」不是更好答案→日常用 default、真難題才 high、max 幾乎別碰＝可省一半用量零損失）、`autoCompact` 門檻拉到 75%（預設 95% 才壓縮、70–80% 就開始 context rot 掉記憶）、deny rules 擋讀 `.env`＋擋 `git push`、`cleanupPeriodDays` 拉到 365（預設只留 30 天歷史會被刪）；🧠 這些是「serious setup 都一樣」的底層衛生。｜ @Simon Scrapes ｜ [原片](https://youtu.be/M2p7OvKLAWw)  ⚡
  - ⏱ **值得完整看完（12 條全可抄、每條一分鐘）**：另有第 13 條心法——「2026 年 prompt 建議反轉了」：不再寫更長更細的 prompt，而是「給結果＋context＋done 長什麼樣、別給步驟」，瓶頸從模型變成「你把意圖講清楚的能力」（呼應 Loop Engineering）。

- **「71 億 token 篩出 6 個每天離不開的 Skill」＝把工作流拆成工位、每工位配一個 Skill** — 🏢🧠 這正是 Alfred 的「完整工序藍圖」法在 AI 上的落地版：作者把「做內容」拆成選題→審稿→封面→圖解→字幕→發布六個工位，每工位一個 Skill，串成一人流水線（過去小團隊一週的活）。關鍵金句：「裝完 Claude Code 吃灰不是工具不行，是順序反了——大部分人先裝工具再找問題；正解是先看每天幹什麼活，再給每一步配 Skill」。｜ @回到Axton ｜ [原片](https://youtu.be/qwsZijT82Jk)  ⚡🔗
  - ⏱ **值得看（方法論 > 工具）**：三個審稿用 Claude 寫、Codex＋Gemini 互相挑刺（兩家 AI 交叉比一家自嗨可靠）；沒有的工具就讓 Claude Code 幫你造（監控誰／看什麼數據／何時跑，三句話講清）。結尾點題：工具給得了，但「怎麼把任務說清楚、怎麼劃邊界、怎麼驗收」才是工具堆與工作系統的差別。
  - 🔗 建議 /ingest → 這套「拆工位配 Skill」可對照 Alfred 的「完整工序藍圖」偏好，升級成一則 thinking-model（AI 協作版工序拆解法）。

- **語音輸入是 AI 時代最被低估的核心技能（Typeless 實戰）** — 🏢🧠 **對口 ctkpro 現況**（P4 團隊已在導入 Typeless）：不是「說話比打字快 3 倍」而已，重點在**打字有摩擦力會下意識省字→丟給 AI 的永遠是被大腦壓縮過的版本**；語音幾乎零摩擦，能把背景/脈絡/你偷懶想略過的細節全倒出來，而「這些你以為不重要的細節正定義了你的品味」。Typeless 的 Ask 功能（選取轉錄文字→問它哪裡該補資訊、用括號標）等於訓練你把意圖講清楚。｜ @Gary Chen ｜ [原片](https://youtu.be/5XeVLt9WejM)  ⚡🔗

### 🔥 熱點卡 3：Harness Engineering 確立為新範式——「不再是 20 個終端，而是管理一個 agent 經理」
⚠️ 翻盤訊號（③ Agent 範式，本期最高價值）· 🔥 5 頻道在談（含 AI Engineer 大會多場）

- **一句綜合**：多方共識成形——**遞歸自我改進短期不靠改模型權重、而是靠優化包在模型外的 Harness 系統**（工作流編排、記憶、評估、權限）。協作範式從「盯著 10 個終端輪詢」升級為「管理一個長跑的 agent 經理，它自己派 worker、跑測試、開 PR，只在需要決策時回來找你」。
- 🏢🧠 **三個可行動洞察**：
  - **Harness 三大設計模式**（@Best Partners TV 拆 Lilian Weng 長文，最系統）：①目標導向工作流自動化（plan→act→observe→improve 循環）②**用檔案系統當持久記憶**（日誌/diff/軌跡塞不進 context，寫成檔案隨模型變強而變強）③**子 Agent＋後台任務**（並行必須「明確可觀測」——存成檔案/日誌，否則中斷即失效無法追溯）。優化對象逐級升高：提示詞→結構化 context→工作流→Harness 代碼→優化器本身。
  - **「管理 manager，不是管 worker」**（@AI Engineer 大會 Steinberger，now OpenAI）：三個變化讓它成立——server-side compaction 讓長跑任務可靠、coordination 讓一個 thread 建/導多專案、triggers 讓 manager 被事件喚醒＝「持久 context＋委派＋觸發＝這就是你的 loop」。金句：「模型進步比 harness 和組織快，設計這些才是下一個工程問題」＋「瓶頸從 token→compute→現在是**注意力**，注意力無法加量，最重要的技能是決定把它花在哪」。
  - **可觀測性是紅線**（@IndyDevDan）：看不見的 agent 無法改進；且他**明確反對**「loop engineering 是未來、prompt engineering 已死」的說法——強調「有一打 agentic pattern 可用，AI 實驗室有動機讓你 token-max」，要保留對 context/model/prompt/tool 五個原語的完整控制。

### 🔥 熱點卡 4：Claude「開智」？Anthropic 全局工作空間論文（J-Space／J-Lens）
