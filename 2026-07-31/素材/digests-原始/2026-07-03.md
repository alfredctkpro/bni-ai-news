## 🟢 工具用法（①⑤ 快線）

- **Loop Engineering 完整拆解：從「prompt 操作者」變「系統設計者」** — 🏢 直接重定義 ctkpro 交付流程：把「人每輪審核」升級成「人設計 loop（Trigger＋可驗收 Goal＋邊界＋hard stop）、agent 自跑自審」，接案交付可從 60 分起跳變 85 分起跳；🧠 這是 AI 協作者的新核心技能。｜ @Gary Chen ｜ [原片](https://youtu.be/kGYFSDd-ZVY)  ⚡🔗
  - ⏱ **值得完整看完（華文最清楚的一支）**：定義＋與 Prompt/Context/Harness Engineering 的層級關係＋「一個任務值不值得做成 loop」三準則（會不會重複／完成標準清不清楚／token 扛不扛得住）＋三種失控（不知何時停→要 hard stop；亂改不該碰的→要定邊界；verifier 失效→驗收要可檢查、產出與檢查分開別球員兼裁判）。結論務實：**大多數人其實還不需要 multi-agent，先從「小範圍、目標清楚、停止條件明確」的小 loop 練手**。
  - 🔗 建議 /ingest → 對應 [OODA循環](../../../4_kb/thinking-models/決策判斷/OODA循環.md)（Loop = 觀察-執行-驗收-修正的 AI 版，且「定向精準決策自然明顯」＝可驗收 Goal 的精髓）＋ [傑文斯悖論](../../../4_kb/thinking-models/財富增值/傑文斯悖論.md)（成本反駁那段）。

- **code base memory MCP：把 codebase 轉成關係圖，agent 改動看得見「blast radius」、省 ~50% token** — 🏢 大型/monorepo 接案最痛的「grep 一堆檔、漏改破壞面」直接解；純 C/C++ 建圖（Linux kernel 3 分鐘、小專案幾秒）、無 LLM pipeline 不會過期；用 pre-tool-use hook 攔截 grep 自動補圖，不靠 agent 記得呼叫。｜ @AI Jason ｜ [原片](https://youtu.be/iWRmtPdFbGw)  ⚡
  - ⏱ **值得看**（實測數據硬）：同問題「改這個 lock 會壞什麼」——用 MCP 33k token、不用 64k token；且能查「哪些呼叫此函式的檔案沒測試覆蓋」。已併進作者的 setup-codebase-harness skill，開源可抄。

- **agent loops / goals / 排程自動化——專業 AI 開發者的實戰用法（Claude Code＋Codex）** — 🏢 四個立刻可搬的用例：①每早掃 production log 找 bug→重現→修→開 PR；②長任務給 Goal（部署上 GCP、跑完整批 issue）；③每日檢查文件與 code drift 自動修；④每週一 triage issue backlog 補 label。成本反駁有力：作者跑一堆 production 自動化每月僅 $10–15、且「本來就要手動 prompt 做的事，用 goal 只是讓它連續跑、沒多花錢」。｜ @Owain Lewis ｜ [原片](https://youtu.be/WRkVuebZqLU)  ⚡🔗
  - ⏱ **值得看**（維護/監控/triage 這類「你懶得做但很有價值」的活最適合自動化）；與 Gary Chen 的 Loop Engineering 互為「理論＋實戰」對照組。

- **自己動手做「Claude Tag」：20 行 Python 在 Slack 復刻，月省 $100** — 🏢 不必買企業方案就能給團隊 Slack 接一個會讀寫檔案、寫 spec 的 agent bot；🧠 手把手示範 agent loop 本質（tool use：給工具清單→agent 要→你跑→回結果）＋ shell 白名單安全（擋串接字元、shlex.split 只查第一個 token、不用 shell=True）。｜ @YAHA学堂 ｜ [原片](https://youtu.be/fQ2lwxVk04k)  ⚡
  - ⏱ **想搞懂 agent loop 底層＋自建內部工具可看**；純聊天 bot →加記憶（撈頻道歷史）→加 tool use →加寫檔，四步遞進很清楚。

### 🔥 熱點卡 3：本地/開源 coding 模型逼近閉源——GLM-5.2 / MiniMax-M3 / Ornith / Qwen 3.6
⚠️ 翻盤訊號（＋Agent 範式）· 🔥 6 頻道在談（9 片）

- **一句綜合**：開源權重模型首次真的擠進前五（GLM-5.2、MiniMax-M3 純智力 top 5），Opus「有真正的競爭者了」；配合 Fable 被下架的教訓，「擁有 / 去中心化你的模型」從理念變剛需。
- 🏢🧠 **兩個可行動洞察**：
  - **模型堆疊（model stack）思維**（IndyDevDan，最有料）：別押單一模型，分三層——SOTA（最難的工程）／workhorse（GLM-5.2、MiniMax-M3，塞進產品、便宜 5–20 倍）／lightweight（Qwen 3.6，本地可全擁有）。「掉一層能力＝降 5x 價格，但能力沒掉多少」→ **product agent 的 tokenomics（用最便宜、剛好過關的模型）才是生意成敗**；且多 provider 去槓桿，某模型掛了你照樣出貨。⚠️ 誠實去 hype：GLM-5.2 ≠ 取代 Opus，是能做 80–90%、贏在價格。
  - **本地擁有的現實**（Bart 9B 實測＋IndyDevDan 硬體帳）：9B 太小（函式寫不全、tool call 常壞、只能降期望/縮範圍），35B 才堪用；真要本地跑 GLM-5.2 級需 $50–100k 硬體、時程約 mid-2027 → **現階段務實解＝租 GPU／多家 serverless provider，別急著自建 home lab**。
- 🧬 **Agent 範式亮點**（Ornith 1.0，Will 保哥中文）：模型「自己寫 harness（loop）」——RL 同時更新「解法」與「引導解法的 harness」，三層防獎勵作弊（鎖邊界／確定性監控／凍結裁判模型否決）。這是「agent 自建 task-specific 工具」的訓練級體現，跟 Anthropic dynamic workflow 同方向。
