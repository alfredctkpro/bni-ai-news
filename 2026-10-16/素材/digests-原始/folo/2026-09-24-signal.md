## 🟡 前沿翻盤

### ⚠️🏛️ 熱點卡 1 · 三家同週發新模型，比的東西從跑分變成「每件事多少錢」 🔥 8 則 🔁（本期主軸）
- **Opus 5.5、GPT-6 Sol／Luna、Grok 4.7 同週發布；兩大家都主打「完成一件事的成本」，跑分反而被官方自己淡化。**
  - **Opus 5.5**（9/22）：Claude 5.5 家族第一個模型，多數工作跟 Fable 5.1 同級。每百萬 token 輸入 4 美元、輸出 20 美元（比 Opus 5 少 20%），**快取讀取從 0.5 降到 0.2 美元（少 60%）**，agent 和寫程式的花費大多落在這項。早期測試者用它稽核並修一個 20 萬行的程式碼庫，**不到 3 小時，Opus 5 要 20 多小時、用掉 2.5 倍 token**。HAProxy 從 C 改寫成 Rust，9.5 小時、成本比 Fable 5.1 少 51%。Pro／Max／Team 五小時用量上限同步調高。
  - **還有三個會影響你日常使用的改動**：①**專抓編造的測試**：只給一份網頁資料寫季度報告，出現一個編造的數字就算不及格，Opus 5.5 寫 18 份過 16 份，Fable 5.1 和 Opus 5 一份都沒過 ②**寫作方式改了**：重點放最前面、少用術語、照使用者的寫作規則走 ③**思考模式不能再關**，而且因為生物與資安能力跟 Mythos 5.1 相當，**大多數資安任務會轉給 Opus 4.8 處理**，資安從業人員要等之後幾週的資安驗證計畫。
  - **GPT-6 Sol／Luna**（9/22）：GPT-6 Astra 的快速、便宜版本，API 比 GPT-5.6 系列的優惠價再便宜 50%，已進 ChatGPT Work 和 Codex。Sam Altman：「**按每任務計價比較，這才是該看的指標，我不認為哪裡有能競爭的**」，並說 API 要做到「每個價位都有最好的模型」。

  - 🏢 **你的 ROI 判準已經是業界的共同語言**：MEMORY 待決的「cost per finished task」不用再自己說服客戶，Sam Altman 替你講了。報價與提案可以直接用「每完成一件事的成本」來講，不講 token。另：**ctkpro 若用 Claude 做資安相關工作（CloudFlare 專研、客戶資安提案），Opus 5.5 會把任務轉給 4.8**，要評估申請資安驗證計畫。

## 🟡 Agent範式

### ⚠️🔗 熱點卡 3 · 「決策模型」成為新的模型類別：不寫字，只挑一個選項 🔥 44 則（Harrison Chase 一人轉發推動大半）＋fox hsiao 長文＋HN 2 個 Show HN 🔁
- **Jev（TypeSafe AI，9/15 發布）與開源的 SemIf，專門做分類、路由、評分；Harrison Chase 說「這是我們內部引起最多 demo 的模型發布，差距很大」。**
  - **它是什麼**：Kahneman「快思慢想」裡的「系統一」模型。輸入一段狀態，**從最多 255 個選項裡挑 1 個**、附信心分數；不吃圖片、不寫文字。fast 那期記過：只收輸入費、輸出免費。
  - **怎麼用（這週實際出現的四種）**：①**當評審**：LangSmith 上線「Jev 當評審」，**每一筆 production trace 都評分，不再抽樣**，LangChain 測了準確度、重複性、延遲、成本 ②**當路由／主管**：有人拿 Jev 與 Opus 4.8 在多 agent 系統裡對比當主管 ③**當過濾器**：Agent Chaperone 用它篩 agent 的工具呼叫與結果 ④**當分類器**：Sydney Runkle 用 SemIf 標記開源 repo 的新 issue。
  - **開源替代**：SemIf（基於 Qwen3.5）在 JevBench 拿 74.7，Jev 75.4；LangSmith Gateway 本週免費提供 SemIf。
  - **冷水（fox hsiao 整理最完整）**：官網說快 193.6 倍，是自家測試的偏高值；Vercel 工程師實測中位數快 4.7 倍。有人拿 1,500 多封商務郵件做分類，**Jev 96.4%，輸給 Google 模型的 98.5%，但費用只要 22 分之一**；真正卡住上線的是讀不了附件。訂票 agent 的作者把「取得網頁狀態」的方式改掉，瀏覽器呼叫從 1,092 次降到 101 次，**任務時間卻只少四分之一**。fox 的結論：「真正花時間的，是把世界整理成一份可靠的狀態。**這種模型接得走的，都是你早就整理清楚的那些判斷。**」
  - 🏢 **分層路由多了最便宜的一層，而且正好補上 9/22 那張「AI 產出驗收條款」的缺口**：人讀不完，就讓決策模型對每一筆產出打分，人只看被標紅的。對客戶可以這樣講：「100% 產出都有機器評審，人審抽查」。

### 🔗 熱點卡 4 · 大規模交給 agent 的前提：程式碼庫就是 agent 的記憶，壞習慣會像病毒一樣散開 🔥 4 則 🔁
- **一個月 2,000 個 PR、19 小時砍掉三分之一程式碼，兩個案例背後是同一件事：先有信任，再放量。**
  - **Lauren Tan（前 Meta React Compiler，現在 SpaceX AI 做 Grok Bot）**：一個月送上線 2,000 個 PR（本人自述，沒有第三方稽核）。她把用 agent 畫成「agent 數量 × 信任」的曲線：1 到 5 個 agent 時盯著每個對話、不停糾正，這段最難離開；**沒有信任就開 100 個子 agent，只會拿到一堆爛 PR、一堆原本好的功能壞掉**。
  - **她最有用的觀察**：「**程式碼庫是 agent 最好的記憶**，因為 agent 很愛延伸它看到的既有模式，好的會被複製，壞的也會。」最常見的例子是 agent 留註解：**agent 用註解解釋自己為什麼不解決真正的問題，然後用短期方案糊過去**，幾週後整個程式碼庫都在學。所以她的團隊直接禁止註解。
  - **她的五層矯正順序**（每次發現在糾正 agent，從第一層往下想）：①改程式碼庫與架構，讓那類錯誤不可能發生 ②靜態分析（lint、編譯器、CI）③給 agent 的規則與 Bugbot ④skills ⑤風格指南（只有人審得住，PR 一多就撐不住）。
  - **Hermes Agent**：Nous Research 讓 Hermes 清一百萬行 Python，**1,393 個子 agent、19 小時，程式碼少 34.4%，估計省下近 200 萬美元工程時數**。
  - **反面**：visidata 有人用 AI agent 修開源 bug，結果有人要求封鎖他們（HN 14 分）；Elastic 的文章標題是「信任，但要跑 benchmark」。開源社群對 AI PR 的接受度還在拉鋸。

### 單則精選

- **harness 對成功率影響小、對成本影響大** 🔁 — 🏢🧠 Melissa Pan 用 7 個模型在 Claude Code、Codex、Pi 三種 harness 上評測，三個發現：①**選哪個 harness 對任務成功率影響很小，但會明顯影響成本** ②簡單的 harness 也有競爭力 ③（原串第三點被截斷，未讀到）。Harrison Chase 的結論：「模型不一定能從原生 harness 得到好處。」→ 補強上週「harness 中間層被刪光」：**選工具時比成本，不用比成功率**；這也讓 Vibe P5 的 eval 有一個直接可比的變數。｜@hwchase17（引用 Melissa Pan）｜[原文](https://x.com/hwchase17/status/2100525372194328691)
