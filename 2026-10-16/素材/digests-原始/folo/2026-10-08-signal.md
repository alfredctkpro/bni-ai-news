> **收斂成一句**：**檢查者要和執行者分開，而且檢查結果不能回饋給執行者**。批准要事先批准計畫、由程式碼執行，不能每次跳出來問；完成要比對實際改了什麼，不能聽 agent 的回報；監控要只讀。主動 agent 把最後一個人工檢查點拿掉了（沒人開口，就沒人在送出前看），所以這三件事得在 agent 開始之前就設好。

## 🟡 Agent範式

### ⚠️🔗🔁 熱點卡 1 · 檢查者和執行者分開：比對實際改了什麼、事先批准計畫、監控只讀 🔥 約 9 則（HN 7：GateBolt、Planlock、Connector、CIPHER、Hotpath、「每個動作都授權了，整體決定還是錯的」；Harrison 轉 Google 論文；Nous；fox）（本期主軸）
- **這週有三個可以照抄的做法，各自對應一種「agent 說的和做的不一樣」。**
  - **比對宣告和實際（GateBolt）**：Sonnet 5.5 在 Claude Code 裡修 Hono 的同一個 bug 11 次（每次全新 session、沒有網路、沒有人按同意）。**11 次都修好了**，維護者寫的 6 個測試全過。但 **6 次的 commit 裡有 agent 沒宣告、也沒提過的檔案**（`validator.ts-E` 這類）。原因很平凡：agent 一開始都用終端機的 `sed -i -E` 改檔，**在 Mac 上 `-i` 會把後面的 `-E` 當成備份副檔名**，多存了一份原檔；agent 用 `git diff --stat` 檢查成果，**這個指令不會列出新檔案**，所以它真心以為自己只改了宣告的那幾個。→ 不是 agent 說謊，是它**用自己的方式檢查自己**。修法很便宜：動手前讓 agent 列出要改的檔案，完成後用 `git status --porcelain` 比對。
  - **批准一次計畫、由程式碼執行（Planlock）**：現在的 agent 只有兩種模式：每次呼叫都問（「第十次你就不看直接按同意」），或完全放手。Planlock 是第三種：agent 先寫計畫，你批准一次，Planlock 擋在 agent 和工具（任何 MCP server）中間，**計畫外的呼叫一律拒絕**。範例：批准「訂單 4711 退款最多 30 歐元 → 寄信給客戶 → 結案」，agent 想退 300 歐元、退別張訂單、先寄信再退款、或退款腳本被人改過，**全部擋下**。檢查是程式碼，不是提示詞，被 prompt injection 的 agent 一樣過不去。Connector（開源）走同一條路：每個動作逐一放行，**營運者可以隨時停掉下一個動作**，每次都留收據。
  - **監控只讀、不回饋（CIPHER）**：見上方對照表第 4 列。
  - **配套**：Harrison 轉 Google 的多 agent 證明論文：「**驗證者從乾淨的 context 開始，探索者的推理就說服不了它**」，這也是 deepagents 讓 subagent 各有自己 context 的原因。HN 一篇〈每個動作都授權了，整體決定還是錯的〉講的是 Planlock 的盲點：**逐步合法不等於整體正確**，所以計畫本身要由人看。Hotpath 走另一個方向：把 agent 跑過一次的軌跡**編成固定的工作流程**，工具呼叫變成一般程式碼，只在需要判斷的地方叫 LLM，環境變了才退回 agent 重錄。
  - 🏢 **ctkpro 交付 SOP 可以直接加一條**：每個 agent 任務「先宣告要改的檔案，完成後比對 `git status`」，零成本，而且正好是 10/06 fast 說的「讀性質，不讀程式碼」中最容易驗的一項性質。**Planlock 的形狀就是 agent 權限治理服務的交付物**：客戶批准一份「這個 agent 能做哪些事、上限多少」的計畫，由程式碼執行，而不是寫在提示詞裡。
  - 🧠 你在 thinkr 跑的 things-sync、folo-digest 都是「agent 自己回報完成」。最便宜的改法是**收尾時跑一個 agent 以外的檢查**（例如 `git status` 比對預期要改的檔案）。

### ⚡🔁 熱點卡 3 · 路由放進 harness：成本中位數少 64%，決策模型開放權重，便宜那層又多兩個 🔥 約 14 則（Harrison Chase 7、Sydney Runkle 轉推 3、Nous 2、Anthropic、fox hsiao）
- **LangChain 給出第二份成對數據，路由的做法也講清楚了。**
  - **數字**：Sydney Runkle 在 LangChain 自己的 coding agent 裡加路由，**每件工作的成本中位數少 64%，品質沒有可量測的下降**；「大部分任務不需要頂級智慧」。
  - **Harrison 的四步**：①先弄懂你的任務 ②弄懂各模型 ③**把路由放在 harness 裡** ④追蹤結果。LangChain 的 coding agent 成本**連兩個月明顯下降**，做法是：**看得見**（每個人用什麼、怎麼用全進 LangSmith）、**每人花費上限**（透過 LLM gateway，要提高上限得找 VPE 談）、優化 harness（路由）。
  - **決策模型開放權重**：Cloudflare 開源 clef／clef-flash；Perplexity 開源 pplx-decider-27b（多模態），**Decisions API 每百萬輸入 token 4 美分、輸出免費**。Harrison：「**harness 換決策模型，應該跟換主模型一樣容易**」；決策模型負責「harness 裡的小判斷（路由、批准、評分）」，大模型負責其他。Jev 甚至便宜到**每次工具回傳後都可以重新選模型**。
