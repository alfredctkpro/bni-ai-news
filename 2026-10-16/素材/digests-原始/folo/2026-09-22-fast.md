## 🟢 工具用法

### ⚠️🔗 熱點卡 1 · 「沒有人在讀」：驗證的瓶頸從工具轉到人 🔥 7 人在談 🔁（本期主軸）
- **產出速度已經超過任何人能讀的速度，白箱審查正在消失；問題是換上來的黑箱驗收，標準由誰定。**
  - **症狀**：宝玉「Vibe Coding 到後來，**想法都不是瓶頸，驗證才是**……功能已經多到測不過來」，連 Codex 和 Claude Code 自己都常有小 bug，「明顯是用 AI 開發太快來不及測試」；他試過 Computer Use 配合測試，效果不理想。voxium 的大公司現場：「**沒有人在讀任何東西，從 L1 到 L7 都在做同一件事：跟 Claude 講話**」。
  - **一個可用的解法（宝玉的非工程師驗收法，20 萬瀏覽）**：把自己當 QA 看三件事：①功能完不完整 ②效能（跑一下看 CPU、記憶體）③**安全是最高優先**（SQL injection、弱密碼這類常識測試要做，拿不準找專業的人）。重點在兩頭：**拆成 agent 剛好處理得了的小模組**，以及**驗收把關**。被質疑後他補充：「保證正確性是目的，可以靠讀推理，也可以靠驗證。**推理看起來再完備，跑不過測試也是錯的**」、「**AI 可以給出論證嚴密、引用齊全但就是錯的方案**」。
  - **代價由誰付**：Shane Parrish 轉述 Tobi 的「**slop grenade**」：讓 AI 產出、不加任何價值（包括不檢查）就傳下去，自己看起來很有生產力，**成本由下一個人付**。geoff：「**loop engineering 開頭是 99% 信仰，接下來是 99% 力氣花在把驗證自動化**，直到收斂到你能在白板上畫出它怎麼運作。」
  - **反方**：Thorsten Ball 問，大家還在用「人好不好讀懂、改得動」來評判模型寫的程式碼，這個標準什麼時候會失效？（＝白箱審查本來就會被淘汰，跟宝玉同方向但更激進）
  - 🏢 **這三條可以直接變成客戶提案的「AI 產出驗收條款」**：黑箱三項（功能／效能／安全）＋拆小模組＋「送出者要附自己驗過的證據」（接 9/17 signal 的 Shopify 那條）。客戶問「AI 寫的你們怎麼保證」，這是能寫進合約的答案。
  - 🧠 **對你自己**：Vibe Coding P5 的私有 eval，本質就是把「驗收標準」寫成可重跑的東西。voxium 描述的狀態，是**沒有 eval 的團隊被迫用人力硬撐**的樣子。
  - 👨‍👩‍👧 CNN 那則（見跨線對照）和 a16z Josh Elman「**程式碼的建造成本大幅下降，但做出正確產品判斷的成本一分錢都沒降**」可以帶進 family 圓桌：孩子要練的是判斷來源、定驗收標準，不是產出速度。

### ⚡ 熱點卡 2 · Claude 產品線重組：Projects、一個 Claude、Docs／Slides 🔥 6 則 🔁
- **Claude Code Projects 把上週 Kiro 的「Maximize agent time」做成產品：你只負責派活和拍板。**
  - **Projects（Claude Code，beta，限部分 Pro／Max 的雲端 session）**：一個對話當主管，任務、bug、補充說明全丟進同一個對話，Claude 決定就地回答、開新執行緒、或轉給正在做這塊的執行緒。每條執行緒是**獨立的雲端 Claude Code session**，有自己的 context、沙箱與 git 分支，**闔上筆電也繼續跑**；開了 PR 會自己盯 CI 與 review 意見、推修正；可設**例行任務**；共用專案指令與專案記憶；沒有程式碼庫也能用（上傳文件做研究、寫報告）。Boris Cherny：「**Projects 是我現在寫大部分程式碼的方式。**」
  - **Cowork 與聊天合併成「一個 Claude」**（Pro／Max 先推）：不用再選模式，Claude 自己判斷任務要什麼。同時 **Claude Docs、Slides、Design** 進到每個對話，Slides 可下載成 PowerPoint／PDF，可設成每週一自動寫週報。宝玉提醒入口在 `claude.ai/artifacts`。Simon：這等於 Claude 變成通用 agent，跟 OpenAI 把 Codex 桌面版改名 ChatGPT 同一個方向，「**功能邊界到底在哪，還要花不少工夫才搞得清楚**」。
  - 另：**Salesforce in Claude**（beta，37 個預建業務 skill）。
  - 🏢 **Projects 的結構跟 9/15 的 Claude Tag on-call 樣板幾乎一一對應**（一層接活、多條執行緒幹活、共用記憶、例行任務），差別是 Projects 只屬於你一個人。→ **Q4 那個 on-call demo 可以先用 Projects 在自己身上跑一輪**，不必等 Slack 整合。
  - 🧠 **正對你 Vibe 節奏的痛點**：上週 Kiro 指出的「60 秒等待迴圈」，Projects 是現成解法。但要搭配熱點卡 1：**執行緒越多，越要先寫好每條的驗收標準**，否則就是 voxium 的處境。
  - ⚠️ Salesforce 與 Docs／Slides 對 ctkpro 客戶是**競品訊號**：「幫客戶做 AI 簡報／週報自動化」這類小案的門檻被原廠吃掉，不要把它當可賣品。

### 單則精選

- **worktree 不遺留：一條可以直接抄進規則檔的條款** — 🧠⚡ 宝玉在額度快重置時丟一堆任務給 agent，隔天發現「完成」的任務其實開在 worktree、**根本沒合併進 main**，一查還有很多這種遺留。他的三段提示詞：①審查（哪些 worktree 還沒同步進 main，同步好的直接刪，沒同步的列出分支、修改摘要、對應 session）②清理（值得合併的合併，不確定的給建議讓他確認）③規則（**完成時必須刪除 worktree 及分支；刪前二選一：合併進 main，或提交到該分支並打 `archive/<名稱>` tag 存檔；編排 subagent 的 session 負責收尾它派生的 worktree；確需保留的要在最終回覆點名路徑與原因，不得默默留下**）。→ 你的 Vibe 流程與 thinkr 都跑 subagent，這條可以原封不動放進規則檔；也是熱點卡 1「任務顯示完成≠真的完成」的具體版本。｜@宝玉｜[原文](https://x.com/dotey/status/2099701340641345828) ⚡

- **MCP 還是 CLI：本週辯論收斂出一條判準** — 🏢 Thariq 說「多數整合 MCP 比 CLI 好」，宝玉反駁：模型訓練過的 CLI（gh、aws、kubectl）幾乎零 schema 成本，deferred tools 只是讓 MCP「不再比 CLI 差」（官方數據：大型工具集的 context 佔用降約 85%）。Simon 給了最有用的分界：**你跑的是能自由上網的完整終端 agent（Claude Code、Codex、OpenClaw），直接呼叫 API／CLI 就好；要做「不那麼 YOLO」的東西，就需要 MCP**：控制能連哪些外部服務、**讓 agent 碰不到 API 金鑰的認證**、給使用者連接服務的介面、完整稽核紀錄。另一個補充：MCP 讓服務端推送最新 API 定義，版本相容比 CLI＋skill 好處理。→ **自己用走 CLI，交給客戶的 agent 走 MCP**，後者正是「可稽核 policy」要的那幾個零件。｜@Simon Willison · @宝玉｜[Simon](https://simonwillison.net/2026/Sep/20/hn-49779718/)｜[宝玉](https://x.com/dotey/status/2100046089214709979) 🔗

- **FDE 的判準：每次從零寫客製碼是外包，不是 FDE** — 🏢🏛️ Anthropic Applied AI 的 Kevin Bai（前 Palantir、Rippling FDE 創始成員）講 FDE 101：Palantir 平均合約 400 萬美元（ServiceNow 120 萬、Workday 60 萬），靠的是 FDE。**客戶買的是「結果」**；但 FDE 成立的前提是**有可重用的平台**，工程師在平台上組裝客製，「**沒有平台，維護成本會吞掉所有利潤，工程師也會因為要維護幾十個不相干的程式碼庫而離職**」。判斷要不要做 FDE：你是不是必須把技術複雜的東西賣給非技術買家？同週 ElevenLabs 執行長補一招：**FDE 屬於產品團隊、不屬於業務**，把現場經驗寫回通用產品，客戶現場就變成免費的研發實驗室。→ **直接打到 ctkpro 的 A/B 路線與 P2 價值主張**：ctkpro 現在是「外包」還是「FDE」，差在有沒有那層平台（或 9/18 yt 講的地基：skills＋eval＋閘門）。越出工具櫃（④商業可接手），但對定位決策夠具體，留在本櫃並建議帶進 board。｜@宝玉 · @小互｜[FDE 101](https://x.com/dotey/status/2099982947394687156)｜[ElevenLabs](https://x.com/xiaohu/status/2101924212537765933) 🏛️🔗

- **Cloudflare Python Workers 正式 GA** — 🏢⚡ 預覽兩年後轉正式支援。原理是 Pyodide（Python 編譯成 WebAssembly）跑在 V8 的 workerd 上，**限制：multiprocessing 與 threading 不能用**。本地開發工具 `pywrangler`（PyPI 套件名 `workers-py`）會完整模擬整套環境。→ **CloudFlare 專研可以加一項**：團隊熟 Python 的服務能不能搬到 Workers、哪些因為 threading 限制不能搬；這也是「代理商走不走」的一個具體判斷點。｜@Simon Willison｜[原文](https://simonwillison.net/2026/Sep/21/cloudflare-python-worker/) ⚡

- **分工省額度：ChatGPT Pro 做設計、Codex／Claude Code 執行** — 🧠⚡ 宝玉：把 GitHub 網址丟給 ChatGPT Pro（要先在設定連 GitHub，才能讀私有 repo、開 PR），請它讀程式碼、寫設計文件，**不佔 Codex 額度**；再把設計文件下載給 Codex 或 Claude Code 執行。有時讓 Fable 與 GPT 6 Pro 各出一套方案，取長補短。→ 接跨線對照的額度下修：**把「想」和「做」拆給不同訂閱**，比在同一家裡切模型更省；也符合 Tara Seshan「用寫作思考的那段不外包」的精神（設計文件你要讀）。｜@宝玉｜[原文](https://x.com/dotey/status/2100757928760262994) ⚡

- **Jev：只輸出判斷、不寫字的「決策模型」** — 🏢 TypeSafe AI（ChatGPT 共同發明人 Diogo Almeida 創辦）推出「System One 模型」Jev：輸入非結構化狀態，**輸出分類、是非、評分與信心分數**，不產生文字。**只收輸入費（$0.042／百萬 token，比 GPT-5 Nano 還便宜），輸出免費**，速度很快，已開放、不用排隊。→ 對「按難度分層路由」是一個新零件：**路由、分類、審核初篩這類「只需要判斷」的步驟**可以用它，把貴的模型留給真的要推理的地方。⚠️ 但小互說「時間線上大部分 Jev 示範都是騙人的」，**要自己用 eval 驗過再用**。熱度高（13 則），屬 ②前沿新物種，建議 signal 接手判斷是不是新類別。｜@Simon Willison · @小互 · @swyx｜[Simon 解說](https://simonwillison.net/2026/Sep/21/jev/)｜[使用指南](https://x.com/xiaohu/status/2101952863316607154)｜[小互存疑](https://x.com/xiaohu/status/2101554334681211326)

- **Stripe 讓模型從零建網路商店：7 家能運作，5 家是 Claude 做的** — 🏢 Stripe 的 UnseriousT-ShirtShopBench：模型要自己建並經營網路商店，全部選擇串 Stripe；7 家能運作的店有 5 家是 Claude 做的，最後選進正式環境的 2 家出自 Fable 與 Opus，但「模型還有一段路要走」。→ **電商／官網是 ctkpro 的客戶產業**：這是「客戶自己用 agent 做店」能做到哪的第一個公開量測，可當報價與價值主張的參照（能跑≠能上線）。｜@Boris Cherny 轉｜[原文](https://x.com/bcherny/status/2099979415040274487)｜[Stripe 的文章](https://breakingchange.blog/p/building-a-t-shirt-factory-factory)
