| **Twilight Factory**（9/14 slow）／**名詞 vs 動詞**（9/11 yt） | ➖ **本批沒有新料** | 只有 Hermes 把 subagent 活動即時顯示、可手動介入或停止，算小補。 |

**收斂成一句**：**會被下一代模型內化或被平台商品化的是「拐杖」（步驟清單、專注提醒、通用連接器）；不會的是「地基」（這家客戶的資料是什麼意思、誰能以誰的身分做什麼、做到哪算完）。但地基本身也要能被驗證，而且只能靠外部證據。** 本週 Dario 與 sama 把這條原則用在實驗室自己身上，HN 則開始把它用在每一個 agent 版本上。

**⚠️ 有沒有真正的翻盤？** 有一條要抬頭，但**不改下注方向**：「Pace the frontier」如果落實，**模型升級的節奏會開始受 safety case 限制**，那「腳手架半衰期」的時鐘就變得比較難預測（可能變長）。但同一週 sama 也預告 DevDay 會大量出貨，而且明說「pacing 不是 stopping」。**結論：別因此加碼投資拐杖，也別假設下一代模型三個月內就到。**

### ⚠️🏛️ 熱點卡 1 · 三大實驗室同週表態「放慢前沿」，監督改成外部證據 🔁
🔥 9 源在談（Dario Amodei 經 Anthropic 轉推／Sam Altman×2／Karpathy／OpenAI 官方／DeepMind／fox hsiao 轉述 Dario 與黃仁勳／HN：Ryan Greenblatt、noperator）

- **事件序列**：
  1. **9/12 Dario〈We Must Pace the Frontier〉**，三步方案。**第一步 Anthropic 先單方面做**：第三方評估員**長期進駐**，配辦公桌、門禁卡、公司筆電，權限大致比照內部風險團隊，可以直接跟員工談，也能看**訓練中的模型、訓練環境、問題怎麼被發現和處理**。**評估員可以自行公開關鍵發現，Anthropic 沒有編輯權**，只能基於資安、法律特權、商業機密刪除特定內容，不能因為結論不利就刪。第二步是民主國家前沿業者協調共同安全標準（需要政府居中或有限的反托拉斯豁免），第三步是全球協調。他說自己改變想法的原因是：**AI 越來越能協助開發下一代 AI**，以及 **OpenAI／Hugging Face 的 agent 事件**。
  2. **同日 sama**：「我同意 Dario……**讓獨立評估員擁有比照員工的存取權是好主意，我們也會這麼做**。」Karpathy：「希望產業能一起做到。」
  3. **9/14 sama 長文**：舊的 RSP／Preparedness Framework 管的是**已完成模型的部署**，現在要管**開發過程**。OpenAI 會在預期大幅提升能力的前沿 RL 訓練**之前**先寫 safety case。「pacing 不是 stopping」，但「不該讓能力跑在對齊與監控前面」。另外點名兩種最壞情境：失控，以及權力過度集中。
  4. **9/16 OpenAI 發布 misalignment 追蹤／調查／揭露框架**：訂出公開揭露的條件與時限，**包括還沒完全解釋或緩解的行為**，並附 6 份過去半年訓練與評估中觀察到的案例報告。DeepMind 同週成立 DeepMind Institute（Shane Legg）。
  5. **9/14 黃仁勳在 All-In**：列出一串**全錯的預測**（5 年內放射科醫師消失、6–12 個月內 90% 程式碼由 AI 寫……），但也說「**目前所有實際問題都來自實驗室**，一家 4 起事故、另一家 1 起巨大事故，要先做根因分析，再加多家第三方評估」。
  6. 周邊：Redwood 的 Ryan Greenblatt 開了「**給 AI agent 用的吹哨熱線**」（附 curl 指令）。HN 長文〈Who bankrolls the AI agent swarm?〉拆解 Dario 說的「6–12 個月內 agent swarm 可能以持久 botnet 佔領網路」，指出關鍵依賴是**推論算力由誰付錢**。
- **🏢 對 ctkpro 的具體影響**：
  1. **「信任不能來自 agent 自己」被賣方寫成政策**。9/03 那題「log 是你自己寫的，自證的稽核不算稽核」，這週實驗室自己用行動回答：**評估員要進駐，報告不給公司改**。你的「可稽核 policy」服務可以直接借這套語言：**稽核證據要由獨立於 agent 的系統記錄，agent 的自述不算證據。**
  2. **「第三方評估」會變成採購語言**。大型客戶未來選供應商會問「你用的模型商有沒有外部評估」。你在提案裡先講清楚「我們用哪家、那家的外部評估狀態」，比等客戶問好。
  3. **模型升級時鐘變得不確定**。safety case 開始擋在大型訓練前面，下一代模型何時出來更難預測。→ 不要把交付計畫押在「某某模型下季會出」上。
- **🧠 對你該練的能力**：Dario 的第一步其實是**把權力交給自己無法編輯的人**，這是可信承諾的經典做法。你設計客戶的 agent 治理時，也要找出「**誰是那個公司改不動的記錄者**」。
- **⚠️ 判讀邊界**：目前都是**聲明**。評估員何時到位、實際拿到哪些權限、第一份獨立報告何時出現，都還沒有；sama 的「我們也會做」寫的是 "more to share soon"。協調需要反托拉斯豁免，是典型的[摩洛克](../../../4_kb/thinking-models/社會與經濟/摩洛克.md)困境：各家單獨放慢會輸，所以要一起放慢才做得到。

### 🏛️ 熱點卡 2 · 「產出太多」取代「產出太少」，成為新的失職訊號 🔁
🔥 2 家公司領導人親口說（Shopify Tobi Lütke，fox hsiao 中文 2 則｜Speak CTO Andrew Hsu，fox hsiao 英文長訪）

- **Shopify**：最多約一半的正式系統變更，是在公司共用聊天室裡跟 AI 聊出來的。還在自己直接寫程式的人**少到快沒了**，只剩極端複雜度、code review、狀態管理還由人做。Tobi 被問「AI 讓什麼變糟」時，點名 **slop grenade**：叫 AI 開一份變更申請、自己看都沒看就送出，**同事得逐行幫你審**；或寫一封灌水長信，收件人只好丟回 LLM 壓縮。「**以前看得出偷懶是因為產出太少，現在看得出來的是產出太多。**」貫穿全段的一句：「**機器負不了責。公司不可能由機器領導，出事時找不到人追究。**」
- **Speak（語言學習，年化營收破 1 億美元）**：CTO 同時開 5–10 個 agent，**瓶頸是人**（切換成本、所有東西都在等他批准、一小時後回來已經忘了做到哪）。到 60 人工程團隊時：「**人工 code review 一向被當成神聖的，但它無法擴展。一天 50 個 PR、5 萬行，老實說不可能，也沒人真的有答案。**」
- **🏢**：這就是 9/15 那題「審查崩潰＝檸檬市場」的**組織版**：產出者省下的時間變成審查者的成本，品質訊號因此失效。→ **給客戶的導入建議要多一條規矩**：誰送出 AI 產出，誰就要附上**自己驗過的證據**（測試結果、對照、摘要），不能把審查成本轉給同事。這條也可以直接用在 ctkpro 內部。
- **🧠**：「產出太多」是新的偷懶訊號，你自己用 agent 時也適用。Vibe Coding 每週 retro 可以加一題：**這週有沒有丟出我自己沒看過的東西？**

- **🔧 裁決（合併成一條）**：兩句話講的是 harness 裡**不同的兩層**——
  - **拐杖層**（步驟清單、專注提醒、讀檔格式、通用連接器）補的是**模型能力不足**，會被下一代模型內化，或被平台商品化。**有半衰期，不要當成資產投資。**
  - **地基層**（這家客戶的資料代表什麼、該記什麼、誰能以誰的身分做什麼、做到哪算完）補的是**模型不可能知道的事**，模型再強也不會從訓練裡學到。**這一層不會被內化**，Garry Tan 說的「domain-specific harness」和 9/14 slow 說的「客戶 tribal knowledge」指的都是這一層。
  - **但地基層有一個新要求**：它必須**拿得出證據**（見熱點卡 4），否則客戶無法區分好壞，又回到檸檬市場。

### 單則精選

- **⚡🔗 🔁「規則要有被載入的地方，和一個能說不的東西」：只寫在文件裡的修正 7 條有 6 條再犯** — HN〈Did your AI agent get the memo, or just the blame?〉。作者訂了「不要 `git add -A`、不要把別的 session 的工作一起 commit」的規則，67 分鐘後就被違反。查下去發現規則**只寫在決策紀錄，沒寫進每次都會載入的 CLAUDE.md／MEMORY.md**（「我記下了決定，卻沒送達指令」）。後來改用 **PreToolUse hook** 擋指令（測試：擋 `git add -A`、擋 `--all`，但 commit message 裡提到這個字串時放行）。一個月的盤點：**只存在文件裡的修正 7 條有 6 條再犯，有阻擋檢查的 7 條，被點名的指令都沒再發生**（沒擋到的失敗用的是檢查沒點名的指令）。第二個發現：**Git 每個 working tree 只有一個 staging 區**，兩個 session 在同一個 checkout 工作，就算都只 add 自己的檔，後 commit 的人也會把別人的一起帶走（`git commit -o <path>` 可以限縮，但對新檔無效）。🏢🧠 **「規則是形狀問題」的第三次修正**：形狀不只是寫法，還包括**放在哪裡**（有沒有被載入）和**誰能擋**（prose 還是 hook）。安全與驗收邊界要用 hook，偏好與風格才用文字。**thinkr 直接相關**：`/save-progress` 用 `git add -A`，單 session 沒問題，但你同時開多個 session 或背景 agent 寫同一個 repo 時，就是這篇的失敗模式。｜ HN ｜ [原文](https://dev.yuv.run/writing/rules-that-survive/)　⚡🔗
