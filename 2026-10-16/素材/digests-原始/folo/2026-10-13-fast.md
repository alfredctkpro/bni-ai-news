## 🟢 工具用法

### ⚡🔗🔁 熱點卡 1 · REA：逆向工程接上 coding agent，「沒有原始碼」不再是護城河 🔥 約 12 則（宝玉 6、歸藏 1、geoff 1、其餘遊戲破解 4）（本期主軸）

- **開源專案 REA（Reverse Engineer Anything）把逆向分析工具接到了 Claude Code、Codex、Cursor 這類 coding agent 上**：看到別人 App 裡有個好功能，可以讓 agent 去拆那個程式、搞懂它怎麼做的。宝玉連四天拿它當玩具，示範了四種完全不同的用法。
- 🏢 **這直接把 10/09 signal 的「無塵室複製」從論文變成這週就能跑的工具**，而且正中 ctkpro 的 Q4 可賣品「**舊系統萃取規格＋重寫**」：客戶那些沒文件、沒原始碼、原廠跑掉的老系統，現在有一條標準路徑可走（拆 → 寫出規格 → 重寫 → 機器驗收）。
- 🏢 **反面也要算**：你交付給客戶的東西，同樣擋不住別人這樣拆。**「因為沒人看得懂所以安全」這條護城河這週正式失效**——報價時別再把「我們做的東西別人接不了」當賣點。
- 🧠 這也是最便宜的學習法：想搞懂某個工具怎麼實作的，直接叫 agent 去拆，不用等人寫教學。
- **四種用法（可直接照抄）**：
  1. **逆向 Claude Slides 編輯器**——先去站上把核心的 script 和 stylesheet 下載下來，再照 REA 官網說明讓 Codex 裝好 REA，做出幾乎完整的功能。
  2. **不反編譯也能懂**——想搞清楚 Codex 怎麼在內建瀏覽器上標記發評論，直接問 REA。
  3. **接 Computer Use 自己去操作**——想學 CapCut 的動態字幕格式，讓它自己去點、去下載、去看怎麼渲染。
  4. **逆向 Claude Design**——發現 GPT-6.1 Sol 接上 Claude Design 的 Skill 後設計能力明顯提升。
- **同一主軸的背景音（成本崩塌的證據）**：Adobe 全套軟體的開源實現、Halo 被反編譯到能在 Android／Linux／Windows 上玩、Overwatch 1 私服、Switch 版暗黑 2 重製版被搬上 iPhone；歸藏在播客裡的判斷是「**一切都會被開源**」；geoff 轉的那句玩笑話同一個意思：「電腦，把 GTA 反編譯、萃取出來，把場景換成我家鄉。」

### ⚠️🏛️🔁 熱點卡 2 · agent 拿到自己的 email：出口破口升級成「身分」破口 🔥 約 20 則（歸藏 12、小互 3、geoff 3、宝玉 2）

- **這週 Grok Bot 開始有自己的 email**（在 X 上 @bot 要一個前綴，bot 收到後要你授權，被占用還能改）。官方給的用途是：**拿去註冊服務、收驗證碼和收據、訂閱簡報讓它自己總結**。
- ⚠️ **這就是 10/08–09 signal「出口破口」的下一步，而且更嚴重**：上一檔談的是「被允許的動作，結果送到錯的人手上」（Shane Mac 的 Slack、Muse 的地址）。但**能收驗證碼的 email ＝ 能自己註冊帳號、能自己過驗證、能自己接收憑證**——agent 從「有嘴巴」變成「**有身分**」。第四層閘門畫的不該只是「訊息送到哪」，要畫「**它能不能用自己的身分去開東西**」。
- 🏢 **對 ctkpro 的權限治理提案，這是這個月最好的新案例**：三層閘門（OS／雲端帳號／計費上限）全都擋不住這一條——agent 不用碰你的機器、不用碰你的雲端帳號，用它自己的信箱就能在外面長出一堆你不知道的帳號。提案要加一條「**agent 可否持有可收驗證碼的身分**」。
- **同時發生的，是「全程不碰本機」已經成立**（這部分是真的好用，別只看風險）：
  - 歸藏讓 Grok Bot **每天早上定時產一支 AI 早報影片**，內容收集、寫程式、影片渲染**全跑在它的雲端虛擬機上，完全沒用本機電腦**，並把提示詞公開、後來直接做成可一鍵安裝的 bot。
  - 他另外示範：把複雜推文串剪成 3 分鐘教學影片（**整套在床上做完、沒開電腦，額度只消耗不到 4%**）、15 分鐘在 Notion 建好自媒體數據看板。
  - **「邪修」用法**：在 agent 的雲端電腦裡裝 Pi 或 DeepSeek Harness 這類 coding agent，**把你其他 code plan 用不完的額度配進去**，讓它調那些 token 去寫程式、渲染影片，閒置額度就不浪費。
  - geoff 從旁觀到真香：「**@bot 真他媽酷**」，而且把它接上自己的平台，**從手機就能開工作負載和任務**。
- **多方觀點**：歸藏＝全面實測、最積極；小互＝整理功能面；geoff＝晚來但轉為重度使用；**本期沒有人在談風險**——⚠️ 這種「一面倒好評」本身就是訊號，風險視角要從 signal 線的 Muse／Shane Mac 案補進來。

### 🔧🔗🔁 熱點卡 3 · 檢查者不該是人：Code Review 只是手段之一，驗收要做成會自己跑的管道 🔥 約 10 則（宝玉 4、geoff 4、Boris 1、swyx 線 1）

- **宝玉這週連續兩天打同一個點，而且打的是上一檔的結論**：
  - 針對「不 review AI 寫的程式碼天就要塌了」的恐慌，他的回應是：「**Code Review 只是保證品質的手段之一**」，並引用一條更兇的：「軟體品質是靠**測試、灰度放量、回滾監控、以及灰度用戶回饋**來保障的。」
  - 另一則點破代價：「這就是**把校驗的成本從寫的人轉嫁給了審查的人**，寫的人自己變成了 agent 和審查者的傳聲筒，或者說另一種**人肉 agent**。」
- 🔧 **這修正了 10/08–09 的「檢查者要和執行者分開」**：方向對，但如果「檢查者」預設是人，你只是把瓶頸從寫移到讀，總量沒降、還多養一個人肉中繼站。**正解是檢查者本身也要自動化**——宝玉自己的工作法就是這樣：**把任務發給 Fable，讓它安排 SubAgent（Opus）去執行，Fable 負責分析、編排和驗收**，他大部分時間在等。
- 🏢 **對 ctkpro 的直接意義**：「舊系統萃取＋重寫」和「公開 repo 資安盤點」這兩個 Q4 可賣品，**賣的不該是「我們幫你 review」**（那是人力，不可規模化、也正是客戶請不起的那一塊），**而是「我們幫你把驗收做成會自己跑的管道」**：測試、灰度、回滾、監控、一支驗收 agent。這同時解掉 9/21 retro「別把判斷也外包出去」的矛盾——**判斷不外包，但檢查要自動化**，兩者不衝突。
- 🧠 **人退出來的那一格，正在被制度化**：Google 正在試點新的軟體工程師面試——候選人拿到一段現成的程式碼，**可以開著 Gemini 一起讀、找 bug、做優化**；面試官要看的是「**你會不會用 AI，以及能不能看出 AI 哪裡答錯**」。另有人主張 SWE 面試可以收斂成兩輪，第一輪就是「你能把系統設計講多清楚」。**「能看出 AI 哪裡錯」已經從個人技巧變成錄取標準。**
- **那「不讀程式碼」之後讀什麼？** geoff 轉述的兩句聽來的話最精準：「**我不想看程式碼，我想看狀態機和活文件**」「**我們現在是控制系統工程師，任何有助於控制訊號的訊號都內聯進來**」。Cindy Sridharan 另有專文：「當你已經不讀、也看不懂程式碼時，怎麼有效地跟 agent 一起 debug。」
- ⚠️ **反方（值得保留的刺）**：陶哲軒在 Caltech 的 Math 2.0 演講被轉成一張圖——「**想像開一種沒有人理解的藥**」。可讀性不是潔癖，是出事時的回溯能力；這也是為什麼「活文件、狀態機、監控」比「讀 code」更該被投資。
- **Boris 的提示詞三問仍然是同一件事的個人版**（10/06 已收，此處只接）：①你要它做什麼 ②要它花多少算力 ③**它該如何驗證自己做對了**。

### ⚠️🏛️ 熱點卡 4 · 供應商風險浮上檯面：半年封 1,140 萬個帳號、政策擴編、分類器太保母 🔥 約 11 則（小互 3、宝玉 3、geoff 3、歸藏 2）

- **三件事同一週發生，合起來是一個營運風險，不是八卦**：
  1. **封號規模**：Anthropic 透明度報告顯示，光 2026 上半年就**封禁 1,140 萬個帳號**，收到 39.8 萬次申訴，**只有 4.2 萬個被撤銷**（撤銷率約 10%）。
  2. **政策擴編**：Claude 使用政策一年多來首次修改，**11/12 生效**，最受關注的一條是使用者不得對 Claude「持續且無必要地辱罵或殘忍對待」。小互整理的適用範圍包括持續羞辱貶低、反覆逼模型表演痛苦、**程式出錯後尖銳批評**、用黑暗故事誘導。
  3. **分類器開始影響生產力**：geoff 公開宣布「**我要棄用 Opus 5.5，Claude Code 裡的分類器太保母、打斷我的 flow 和開發迴圈，不堪用**」；他轉的一則更直白：「如果你得即時繞開模型的限制才能用它，那模型多好都沒意義。」
- 🏢 **對 ctkpro 這是 Q4 的真風險，不是談資**：你正在把 Claude 放進**客戶交付流程**（Vibe Coding 五階段、Claude Tag on-call demo、talk-prep）。上面三件事合起來＝**單一供應商可以在你不違法、甚至不違規的情況下，單方面中斷你的生產線，而申訴成功率只有一成**。
- **可操作的三件事（都很便宜）**：
  - **把「帳號被停」寫進交付風險清單**，客戶合約裡的 SLA 不能預設模型供應商永遠在。
  - **別把公司營運綁在單一帳號上**：宝玉實測兩個 Claude Max 20x 帳號「註冊時間久的那個不太耐用、新的耐用得多，用法一樣」——配額行為本身就不透明。
  - **降低誤判機率**：歸藏指出 Anthropic 的反蒸餾說明文，反過來看就是一份「怎麼別讓系統誤以為你在蒸餾」的指南，**新註冊帳號被快速封禁多半是這個原因**。
- **商業觀點（小互）**：1,140 萬被封帳號打三折還有三百多萬人「死活都要用上 Claude」——他認為這裡面有生意。🏢 ⚠️ 這條**不建議碰**，但它說明灰色代理市場正在長出來，客戶可能已經在用；盡職調查要問「你們的 Claude 額度哪來的」。
- **其他不穩定訊號**：Claude Startups 計畫 10/6 升級後**三天就暫停了兩項最值錢的福利**（免費一年 Team、$1,000 API 額度），原因是申請量遠超預期；Claude Agent SDK 和 `claude -p` 的使用限制似乎放寬了，但**沒有官方聲明**，宝玉判斷更像單方試探。
