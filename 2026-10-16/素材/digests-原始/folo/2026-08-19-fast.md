- **Pi 兩位作者見解：代碼即真相，不需記憶系統/RAG；Bash 足夠、大多數時候不用 MCP，skill + 腳本就夠** — 🏢🧠 直接呼應你「skill/腳本優先、少客製」的偏好；是「工具層越薄越好」這波的理論支點。 ｜ @dotey ｜ [原文](https://x.com/dotey/status/2089127369596383363)  🔗 建議 /ingest
- **Peter Steinberger：code mode 已進現代 harness，cli/mcp/tools 都只是 agent 寫的一段 JavaScript，那些界線不再重要** — 🏢 若成立，MCP 生態的必要性下修，你評估工具棧時要納入；🧠 「讓模型自己寫程式組合能力」的範式。 ｜ @steipete ｜ [原文](https://x.com/steipete/status/2089799774824517879)  🔗 建議 /ingest（與 Pi 作者併一則）
- **宝玉：從 ChatGPT 網頁版（Pro）直接讓它改代碼、提交 PR** — 🧠 不必打包整個 repo 上傳，接 GitHub 就能跑 Deep Research→改碼→PR 的閉環（他補：用 GitHub CLI 比 access token 安全）。 ｜ @dotey ｜ [原文](https://x.com/dotey/status/2089072890104725788)  ⚡
- **宝玉：不用擔心代碼命名，agent 不是靠猜關鍵字找代碼，是讀片段順著上下文定位** — 🏢 破除團隊常見迷思（「命名不好 AI 就找不到」），對帶團隊導入 AI coding 有用的說法。 ｜ @dotey ｜ [原文](https://x.com/dotey/status/2089163694173282514)
- **Simon Willison：「Don't classify. Hallucinate!」用 LLM 給 1,856 個舊標籤自動打標** — 🧠 反直覺 prompt 技法：不做嚴格分類、讓模型「幻覺」出合理標籤反而好用，適合整理積壓內容/知識庫。 ｜ Simon Willison ｜ [原文](https://simonwillison.net/2026/Aug/14/dont-classify-hallucinate/)  ⚡
