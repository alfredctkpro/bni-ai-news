## 🟢 工具用法

### ⚡🔁 熱點卡 1 · Opus 5.5／Sonnet 5.5 使用手冊：檔位比模型更影響帳單 🔥 11 則（本期主軸）
- **官方和重度使用者這週同時給出「怎麼用才省」的具體設定，結論是：多數人的浪費來自檔位開太高、快取被自己弄斷。**
  - **effort 檔位怎麼選**（Claude Code 團隊 Thariq 的文章，宝玉整理）：low＝腦力激盪、畫草圖、小改動；medium＝大部分日常開發；high＝需要驗證、邊界情況多的，例如在老程式碼裡修 bug；max＝讓它完全自主攻一個難題。**檔位真正決定的是「它花多少力氣驗證，以及替你做多少假設」**：同一個模糊需求「做一個健身紀錄 App」，low 只做紀錄表加一張圖，max 自己加了熱力圖。**如果先讓 Claude 反過來訪問你、把需求問完整，不同檔位的產出就很接近。** Thariq 自己的流程：讓 Claude 問你漏了什麼 → low 檔做 → 看方向 → 最後切 high 做驗證和測試。`/effort` 可在對話中途切換，Opus 5.5 和 Fable 5.1 切換不會讓快取失效。
  - **別開 max**：歸藏實測 Sonnet 5.5 在 max 檔下的花費快追上 Opus 5.5，甚至接近 Fable 5.1；Simon 測兩個 5.5 模型的 max 檔都會想到用完 128K token 還交不出東西。**Opus 5.5 預設是 medium（Opus 5 是 high）**，而且同一檔位 5.5 想得更多，**舊的檔位設定不要照搬**。
  - **快取才是帳單大宗**（ClaudeDevs 文章）：每一輪都要把整段對話重送一次，所以帳單看的是「跑幾輪」。①不相關的任務用 `/clear` ②要保留前情用 `/compact`，**在快取失效前做** ③訂閱用戶快取保留 1 小時，API 只有 5 分鐘：離開 6 分鐘，12 萬 token 上下文的下一輪從 0.02 美元跳到 0.60 美元 ④**對話中途換模型、接上或斷開 MCP server、第一次開快速模式，都會讓下一輪按較貴的寫入價重付**。
  - **Sonnet 5.5**（9/28）：價格和 Sonnet 5 一樣（每百萬 token 輸入 2／輸出 10 美元，Opus 5.5 的一半），Terminal-Bench 4.0 得分 70.6%（Opus 5.5 最佳 66.4%），GDPval 辦公任務 1844 分幾乎追平 Opus 5.5 的 1846。**官方自己說：開放式、需要持續判斷的複雜工作，Opus 5.5 仍明顯較強。** 它現在是 claude.ai 免費版的模型。Haiku 5.5 幾週內發布。
  - **使用者體感**：宝玉「Opus 5.5 寫作比 Opus 4.6 還好」、「很耐用，愣是沒在重置前用完」；Mckay Wrigley「Opus 4.6 的個性加上 Fable 5.1 的智力與品味，而且額度多 25%」。
  - 🏢 **給客戶報 AI 維運成本時，這份設定就是報價的變數**：同一件事，檔位和快取習慣可以差十幾倍。Q4 如果賣「agent 導入」，**預設檔位、subagent 分工、快取紀律**可以寫成交付物的一頁 SOP。
  - 🧠 **正對你的 ROI 判準**：`/usage` 的每任務成本計算器，可以直接當 Vibe P5 私有 eval 的第一個量測點，不用自己造。

### 🔗🔁 熱點卡 2 · Opus 5.5 用程式碼做影片：一週刷屏，但「模型強不是你強」 🔥 30＋則（宝玉、歸藏、Riley Goodside、小互、Alex Albert）
- **不用任何生成影片模型，Opus 5.5 自己寫 p5.js／three.js／Remotion 逐幀畫、找免費語音、用 ffmpeg 合成，做出有配樂、會卡點的解說片與產品宣傳片。**
  - **做法（可直接抄）**：宝玉的《什麼是 Transformer》提示詞只有四句：「用 js 做一支影片，主題是什麼是 Transformer，要深入淺出、讓高中生也看得懂，不只 high level 說清楚也要有細節，包括注意力機制甚至一些數學概念；你可以用任何工具或安裝工具，可以上網查；請給我驚喜。」它自己找了**微軟 EdgeTTS** 當配音、用 **Remotion＋KaTeX** 渲染公式。長一點的做法：要它分里程碑推進、**不斷渲染靜幀、自己看、誠實批評再修**。Alex Albert 用 Opus 5.5 驅動 Blender 一句話做黏土動畫。歸藏把 Opus 5.5 做宣傳片的能力整理成 `guizang-product-video-skill`，讓便宜模型也能做出八成效果。
  - **背後的教訓（宝玉）**：「**給規範，不給模板**。我做 PPT skill 時放了一堆模板，後來學到不給模板、給一套顏色與樣式規範，模型自己決定做成什麼樣。模板是專家捷徑，規範加模型能力是笨辦法，但『苦澀的教訓』說通用方法終將勝過專家捷徑。」做影片甚至不需要 skill，給它 TTS、畫圖工具、ffmpeg 和瀏覽器就夠。
  - **反方**：小互「**沒有品味、缺乏相關專業經驗，做出來的東西讓人不適，最後只能自嗨……模型強不是你強**」；「每個模型出來都一頓炸裂，然後就沒然後了，最後還是拿它來寫文件」。
  - 🏢 **「幫客戶做產品宣傳短片／簡報動畫」這類小案的門檻被打到接近零**，跟上週的 Docs／Slides 同一個訊號：不要當可賣品。能賣的是**知道這支片要對誰講什麼**（腳本與取捨），不是做出來。
  - 🧠 **BNI／Retro 演講可以直接用**：talk-prep 產出大綱後，挑一個概念丟這四句提示詞做 30–60 秒解說片，時間盒 1 小時。**把宝玉的「給規範不給模板」帶回你自己的 skill**（ctkpro-slides 的模板是不是該換成一份設計規範？）。
  - 👨‍👩‍👧 **《什麼是 Transformer》那組提示詞，把主題換成孩子正在學的東西，就是一支專屬教學片**。更值得跟孩子一起做的是反面那句：讓他看兩支片，一支有想清楚要講什麼、一支只是炫，問他差在哪。

### ⚡🔗🔁 熱點卡 3 · plan 模式要被拿掉，換上「寫下來的方案文件」當驗收依據 🔥 9 則（宝玉 5、Thariq、geoff、卡茲克、小互）
- **大家不約而同放棄 plan 模式，改用一份文件同時做三件事：讓人確認方向、在多個 agent 之間傳遞上下文、事後當驗收標準。**
  - **宝玉的「顧問驗收迴圈」**：①`/advisor fable`，讓 Opus／Sonnet 遇到拿不準的事自己去問 Fable ②複雜問題先讓 Fable 寫技術方案文件（**文件裡寫清楚技術細節與怎麼驗證**）③確認後讓 Opus 執行，並加一句：「**完成後讓你的 advisor 驗收，有問題就照反饋修，修完再驗收，直到通過為止**」，搭 `/goal` 更好。好處是**你不用在兩個會話之間來回傳話**，而且比讓 Fable 全程編排省很多 token。
  - **他的專案起手式**：PoC（看能不能跑）→ Claude Design 先做設計、不急寫程式 → MVP → 迭代。**文件管理**：全放 `docs/`、每份都小、主文件只放概要和連結（漸進式揭露）、README 當目錄、**AGENTS.md 強制「改功能就要改對應文件」**，但人仍要定期檢查。
  - **重寫舊系統**：卡茲克說「比重構爛程式碼更有效的是：把舊專案萃取成功能文件，讓最新模型照文件原地重寫」。宝玉補：**舊的單元測試沒什麼用（程式碼都換了），但舊的 E2E 測試很有用**，重寫前先讓 AI 補 E2E 覆蓋主要流程，Web 用 Playwright；而且別指望一次寫完就穩，驗證時間省不掉。
  - **geoff 的反向版**：以前先寫高階設計文件（HLDD）再做，現在是**做完才寫**，用 pre-commit hook 與 skill 強制 agent 自動更新 HLDD；**上半頁是人寫的「為什麼、成功怎麼量」，下半頁是 agent 維護的「怎麼做」**。
  - **官方風向**：Thariq「我不覺得模型還需要 plan 模式」，考慮把 Shift+Tab 改成切換 effort 檔位。
  - 🏢 **這就是 ctkpro 可以寫進接案流程的交付格式**：每個需求一份「方案＋驗收方式」文件，上半頁客戶簽、下半頁 agent 維護。重寫客戶舊系統的案子（行政院那類維護案）可以直接照「萃取功能文件＋先補 E2E」報價。

### 🏛️🔁 熱點卡 4 · 驗證往機器走：形式驗證、屬性測試，以及「公開原始碼反而不安全」 🔥 8 則（Boris、geoff 4、Simon、steipete 2）
- **當產出便宜到讀不完，驗證開始變成「讓模型建模找反例」，而攻擊方也用同樣的便宜在掃你的程式碼。**
  - **形式驗證變平價**：Boris 用 Opus 5.5 以 Lean 形式驗證 Claude Agent SDK，「幾句提示詞＝16 個 PR，修了各種 bug 與 race condition」。做法不是整個程式碼庫都驗，而是**挑最容易出事的狀態機或併發區塊建模 → 找反例 → 重現 → 修**。他自己不太會 Lean 和 TLA+，但 Claude 很會。
  - **geoff**：「推論速度很快就不是瓶頸，**瓶頸會變成編譯與驗證工具鏈多快**」；他用 Hegel 做屬性測試（property-based testing），對 NixOS 跑出了真問題。steipete：CI 成了每個工程團隊的最大瓶頸，他打算**讓 Codex 決定哪些測試真的要跑、CI 改成每小時跑一次**。
  - **攻擊面**：有人快做完「**30 天內、100 美元，逐行稽核 GitHub 前 1000 大 repo**」；geoff 的結論：「在 LLM 自動紅隊的時代，**把原始碼放上 GitHub 會降低它的安全性**。」另外 Astra 與 Daybreak 在 libuv 裡找到一個約 14 年的舊 bug 與 8 個長期記憶體洩漏。
  - Simon：「跟 coding agent 工作越久，我越確定**它讓軟體工程變得更難**。要發揮它的全部潛力，需要非常高的紀律與知識。」
  - 🏢 **兩件事可以直接接 Q4**：①**客戶公開 repo 的資安盤點**（Zeabur 事件同一脈絡：別人花 100 美元就能掃完你，你自己先掃）②付款、訂單、排程這類**狀態機的「建模找反例」**，用 Boris 的四步驟當一項加值服務。
  - 🧠 Vibe P5 的 eval 除了「每任務成本」，可以加一條「**挑一個最容易出事的模組做一次建模找反例**」，練的是 geoff 說的那種工程功夫，而不是提示詞。
