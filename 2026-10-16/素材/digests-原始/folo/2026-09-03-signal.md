- **問題一：誰賠？（新的、上期沒有）** — 一篇獨立指南《**當 AI agent 造成損害時誰來付錢：合約、保單，與那道缺口**》直接處理責任歸屬與保險真空。硬證據同週兩起：**Meta 一位資安研究員的 AI agent 誤刪了她的信件**（PCMag 報導）；另一起是 **agent 誤讀風險訊號、動了 120 萬美元的交易**（該團隊事後做了工具）。🏢 **這對你是需求訊號，不是恐怖故事**——「誰賠」一旦進了合約與保單，客戶就必須有**書面的權限與責任邊界**，而寫那份文件正是你的工序。
- **問題二：誰簽收？** — **Microsoft 官方發布《AI Agent Shared Responsibility Model》**（放在 Azure security fundamentals 官方文件裡）。🏢 **雙面刃，要分開讀**：❌ 通用層又被大廠佔一格（呼應你「不做通用平台」的判斷，本週再被證實）；✅ **但「責任分界」被官方寫成文件，等於替你創造需求**——客戶讀完官方文件的下一句一定是「**那我這邊該負的那半，具體要做什麼？**」那一句就是你的入口。同向的還有 **AgentGate（為 agent 的 SaaS 動作產生「簽名收據」）**。
- **問題三（本期最尖銳的一句）：log 是你自己寫的** — HN 上一則 **Ask HN** 把整個 agent 稽核市場的底層假設一刀劃開：**「AI agent 行動了。你的 log 說是這樣。但 log 是你自己寫的。」**（原文：如果你在 production 部署 agent，你們怎麼處理可稽核性？什麼樣的東西才會讓你信任它？）🏢 **這是你那條「可稽核 policy」服務的核心賣點與核心難點**——**自證的稽核不算稽核**。→ 這句話要帶進圓桌當拷問：你要賣的是「幫客戶寫 policy」（顧問工序，今天能接案），還是「**可被第三方驗證的稽核**」（產品，要跟基金會標準賽跑）？**上期的兩題（要不要做／做成什麼形狀）本週被這句話逼出了第三題：可驗證性由誰提供？**

### ⚡🔗 熱點卡 4 — **記憶的難題不是「怎麼寫進去」，是「怎麼忘掉」——本週它有 runtime 了**（直擊你的 MEMORY.md 待決）
🔥 8 源在談（Colin Francis／Harrison Chase×3／LangChain 官方／Hunter Lovell／george salapa／MLMastery）

上期（8/27 熱點卡 4）你收到的是「有人開始做了」；**本週它從想法變成兩個版本號**：

- **openwiki v0.4.0 · claims runtime**：給你的 wiki 一個**持久的事實來源（persistent source of truth）**，用途明說是——**幫助它「遺忘」與「自我修正」**。Harrison 同日宣布 **openwiki 已支援 OKF 2.0**（開放記憶標準，7 月起追的那條線）。
- **openwiki v0.5.0（9/1）**：主題是 **durable ＋ resumable**——Colin Francis 的開場問句很傳神：「**比『長時間執行的工作失敗』更糟的是什麼？答：長時間執行的工作失敗，然後把所有東西一起賠掉。**」
- **第三方怎麼看（本卡最有價值的一句）**：Hunter Lovell——**「claims 是『coding agent 的更好記憶長什麼樣』這個問題的很酷的探索：現在它看起來像 inline comments……」**；george salapa 則指出結構性的收斂：**「跟 langchain wiki 非常像？也很有趣的是，所有東西都在塌縮成某種形狀的 loop ＋ instruction。」** Harrison 回應時把話講白：**「Wiki 是把知識表示成簡單易懂的形式的絕佳方式。」** 同週 openwiki 也做了 **Cursor 整合**（繼各家 coding agent 之後）。
- **🏢🧠 對你的具體影響（這是本期最能直接動手的一則）**：你 MEMORY.md 上掛著「**缺汰換機制**」——尺是「記憶是算力的函數」，而且你自己記了「今天又刮了 8 輪才壓回」。**claims runtime 給的正是這個缺件的一種實作**：不要靠人每次手動刮，而是**把「事實」與「敘述」分離**——事實（claim）可被新證據推翻、可被標記為過期；敘述（MEMORY.md 的行文）由事實生成。→ **可立刻做的最小實驗**：拿 `context/MEMORY.md` 的「Pending Decisions」段當白老鼠，每條加一個**過期條件**（「當 X 發生時這條作廢」），跑一個月看是不是就不用刮了。這比再刮 8 輪便宜。

### 單則精選

- **⭐「我們花了多少錢」是沒用的問題，該問「哪個 workflow／哪次 tool call／哪條 prompt path／哪個 retry 花的」——成本對賬要下到 trace 層** — Harrison Chase 本週最有操作價值的一則：**cost reconciliation at the trace level**。🏢🧠 **這直接命中你懸著的「投入 ROI 判準：核心＝cost per finished task」**——你一直卡在分母怎麼算，這則給了答案的形狀：**分母不是「總帳÷任務數」，是「每條 trace 歸因」**。因為同一個「任務」裡真正燒錢的往往是**重試迴圈與某一條走岔的 prompt path**，而總帳看不見它。→ 具體動作：投資戰情室與 Vibe Coding 的每次 agent 執行**留 trace**，先只做一件事——**標出「retry 佔總成本的比例」**。若這個數字大，那省錢的槓桿不是換模型，是修那條路徑。呼應同期兩則：①**「Agent traces 不該只對 infra team 有用——對多數 builder，最快的 debug 方式是重播對話＋tool calls」**；②實戰案例 **Podium**「agents 看起來壞了，LangSmith 顯示的真相是：**agent 是基於它拿到的 context 完全理性地行動**」——**bug 在 context，不在 agent**。｜ @hwchase17 ｜ [trace 層成本對賬](https://x.com/hwchase17/status/2094459616033902909)｜[trace 該給 builder 用](https://x.com/hwchase17/status/2094985765629628904)｜[Podium：bug 在 context](https://x.com/hwchase17/status/2093361527101510116)　⚡🔗

- **「最好的科學 AI agent 會由 Benchling 做出來，不是 Anthropic 或 OpenAI」——many-agent world，每個都是領域專屬** — Harrison Chase 的一句斷言：**強烈相信一個多 agent 的世界，每一個都是特定領域的**。🏢 **這是本期對 ctkpro 定位最直接的一票**——它說的是：**懂領域的人做該領域的 agent，模型公司做不了**。但要誠實面對本期的反證：**Anthropic 同週推出零售業 blueprints、還推 MHS 想標準化實驗室與製造設備**（見前沿櫃）。→ **判讀（不是結論，是圓桌的問法）**：模型公司會往「有大量同質客戶的垂直」（零售、客服）走；**真正安全的位置是「客戶數少、規則各異、tribal knowledge 重」的領域**——這正好是你 ctkpro 現有客戶的形狀。**這條張力值得在 board 圓桌上跟「agent 權限治理要不要做」一起拍。**｜ @hwchase17 ｜ [原文](https://x.com/hwchase17/status/2093083519358799984)　🏛️
