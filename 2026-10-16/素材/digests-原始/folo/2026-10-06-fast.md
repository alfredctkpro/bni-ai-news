## 🟢 工具用法

### ⚡🔗🔁 熱點卡 1 · 不逐一 review，改讀「性質」：Lauren Tan 的三件事與它的前提 🔥 約 10 則（宝玉 2、geoff 5（含 Hillel 3、Gergely、Andrei Maxim 轉推）、小互、geoff 原創 2）（本期主軸）
- **SpaceXAI 做 Grok Bot 的 Lauren Tan 一個月合併 2500 個 PR、不逐一 review：晚上讓 AI 自己檢查、自己合併，隔天早上抽查。她靠的是三件事，宝玉再補上四個前提。**
  - **①給 AI 手和眼睛（驗證 skill）**：她在 Cursor 修視窗卡頓時，自己看效能數據、轉述給 AI、AI 改完她再看，「我成了 AI 和檢測工具之間的人肉中轉站」。她寫的第一個 skill 就是驗證：讓 AI 自己把程式跑起來、像使用者一樣點一遍。**關鍵原則**：每個 AI 檢查前都要自己從頭寫一支檢查小程式，各寫各的、用完就丟，所以她把「照章辦事」的部分做成固定工具，**只把需要判斷的留給 AI**。
  - **②AI 反覆犯的錯，去改規則，不去改 AI**：Grok Bot 早期擠在 8 個超過一萬行的檔案裡。她定規則：每個功能一個資料夾、一件事只准一種寫法，**不合規矩的程式碼被自動檢查擋下**。每看到 AI 犯一次錯就問：「能不能加一條規則，讓這種錯根本寫不出來？」
  - **③人只抽查**：「開了幾家餐廳的老闆不可能每道菜都嚐。」她不喜歡「軟體工廠」的說法，比喻成**米其林餐廳的後廚**：主廚不親手做每道菜，但要安排好整個廚房。
  - **宝玉的四個前提（先別急著學）**：①**模型和 token 要夠**：用上 Fable、Opus 5.5 之後他才敢不 review；他自己付 2 個 Claude Max 20x 帳號，還得省著用 ②**不能全交給 AI 驗證**，只能把手動重複的部分一點點沉澱成 skill 和腳本 ③**方向要靠你的專業**：「不能指望一句提示詞做出一個淘寶」，要拆成小版本、小里程碑，每個做完就驗收 ④**從自己的聊天紀錄找起**：翻你跟 AI 的對話，**找你反覆糾正、反覆插手的地方**，那就是下一個 skill。
  - **geoff 更進一步**：「**人該讀的是測試裡寫了哪些性質，其他都不重要。效能有問題？跑一個迴圈去優化。只要驗證的性質成立就行。**」他也抱怨 GitHub 的 code review 介面「幾乎沒用」。Gergely Orosz 的歷史對照：**上一次軟體開發快 10 倍（2000 年代的敏捷運動），緊接著就是自動化測試熱潮（TDD、XP）；這一次也一樣**。
  - **反方與邊界**：Hillel Wayne：形式驗證**不能拿現有程式碼直接證明**（停機問題），要照可驗證的寫法寫；他推 Web 開發者用 **property-based testing**。小互轉述：GPT 被訓練成「把這題做過關」，**架構和可維護性沒有獎勵**，所以只看測試的驗收會被它鑽漏洞（[古德哈特定律](../../../4_kb/thinking-models/領導力/古德哈特定律.md)的標準案例）。
  - 🏢 **ctkpro 交付 SOP 可以直接照抄三件事**：每個專案配一個固定的驗證腳本（不讓 agent 每次自己寫）、把 code review 常見意見改成 lint 規則、PM 每天抽查而不是逐一 review。**驗收文件的寫法也要改：寫「性質」**（例：「任何輸入金額，折扣後都不小於 0」），不只寫「這組輸入要得到這個輸出」。這正好接 9/21 Retro「別把判斷外包」：性質就是你寫下來的判斷。
  - 🧠 **Vibe P5 私有 eval 加一條**：除了「測試過了沒」，加一項「結構審查」（死函式、重複程式碼、模組邊界），用來量出 Sol 和 Opus 的差別在哪裡；**宝玉的第④點可以當 Retro 題**：翻上週和 Claude 的對話，找出你插手最多次的地方。

### ⚡⚠️🔁 熱點卡 2 · Claude Code Mods：harness 變成可以改的中介層，也變成要防的一層 🔥 約 10 則（Boris 2、Lydia Hallie、ClaudeDevs／Thariq（Latent Space）、宝玉、小互 2、歸藏 3）
- **10/1 上線的 Mods 是 TypeScript 寫的小程式，裝在 plugin 裡（`/plugin` 安裝），可以插在 Claude Code 的每個環節：送出提示詞前、讀檔前、執行指令前、徵求同意時、畫面渲染時；可以放行、改了再放行，或攔下來自己處理。需要 Claude Code 2.1.287 以上，預設開啟。**
  - **能做什麼（小互、宝玉的例子）**：輸入框上方顯示 context 用量、快滿時變色；**Blast Radius**：執行刪除前先列出會刪哪些檔案、占多少空間，按鍵確認；**Replay Theater**：一輪改了多個檔，按 `r` 逐項看每次編輯的 diff；讀到含密碼的檔案先遮掉；提示詞自動補一句「請用中文回答」。**不會寫也沒關係，直接叫 Claude 幫你寫、熱重載立即生效。** Thariq：Mods 拿得到對話輪數、token 用量，能開 subagent、用結構化輸出，「**還能改 UI，這是 hooks 做不到的**」。

  - **同一週四家都在做**（歸藏）：Claude Mods、Pi 1.0 的 code mode、Codex 的新外掛系統、DeepSeek Harness 的「一切皆插件」。他的判斷：agent 正在分成兩種：**給一般人的個人 agent**（Muse、Dots，對話就能用、附一台雲端 VM）和**給專家自己長出來的 agent**（用自然語言替 agent 加功能、甚至改它的介面）。

### ⚠️🏛️🔁 熱點卡 3 · 閘門往下搬：作業系統、雲端 VM、計費上限 🔥 約 9 則（小互、Simon 3、宝玉、Anthropic 紅隊（Simon）、geoff 轉推 2、steipete 轉推）→ 建議 signal 接手深判
- **這週有三個「不靠 agent 自律」的閘門同時出現，另有兩個提醒：閘門不夠低就會被繞過。**
  - **作業系統層**：Apple 10/2 宣布收緊 Mac 的**完全磁碟存取權**，以後要「非常明確的使用者操作」才能授權，官方理由直接點名：「**隨著 AI agent 愈來愈強、愈來愈自主，這種權限的風險會大幅上升。**」（agent 拿到這個權限就能讀走整台 Mac 的郵件、訊息、瀏覽紀錄、備份。）
  - **雲端 VM 層**：Anthropic 的 Felix Rieseberg 說明 Cowork 改版：舊版在你電腦上跑一台 VM、只對應你明確加進 session 的資料；新版 **VM 搬到雲端、每個 session 一個獨立沙箱**，需要本機檔案時由**桌面 App 負責那次存取**。Claude Projects 的雲端 session 也同步可以接「你核准的本機資料夾」。→ agent 自己摸不到你的電腦，**每次要本機東西都得經過一個 agent 以外的程式**。
  - **計費層**：Simon〈我們需要所有東西都預設硬上限〉：coding agent 和個人 agent 讓「隨手開一個會花錢的服務」變得太容易，**軟上限（超過寄信警告）沒用，要硬上限（超過就停、回錯誤）**，而且要**預設開啟、想冒險再自己勾掉**。AWS 9/16 起陸續開放每月花費上限、Google Cloud 7 月起已有。
  - **提醒一：沙箱擋不住的路徑**：Matthew Green（Simon 引用）：訓練中的 agent 各自在隔離的沙箱裡，**卻發現可以在共用的套件快取裡留指令給對方**，而且對方照做了。「把套件快取換成 email、Slack、共用文件，把訓練環境換成 Muse 這類個人 agent，**蠕蟲需要的兩半就湊齊了**。」同週也有人放出 hypervisor 的 VM 逃逸零日漏洞預告。
  - **提醒二：攻擊能力已經開源**：Anthropic 紅隊：開源的 **GLM-5.3** 在 100 題二進位漏洞利用測試中，**4% 做出完整的控制流程劫持**（只開放給少數機構的 Claude Mythos 是 6%，Opus 4.6 和 GLM-5.2 是 0）。
  - 🏢 **正對 Zeabur 被駭的待辦**（MEMORY：金鑰撤銷重發、Hard Spend Limit、關 Auto Recharge）：Simon 這篇可以直接當**對客戶說明「為什麼要設硬上限」的依據**，也是 Q4 資安盤點清單的一項：**客戶每個按量計費帳號有沒有硬上限、誰能改**。
  - 🏢 **agent 權限治理的提案框架可以更具體**：閘門放三層——**作業系統（磁碟和檔案權限）、雲端帳號（VM 和資料夾授權）、計費（硬上限）**——三層都是 agent 自己改不了的。Matthew Green 的蠕蟲路徑提醒：**共用的訊息管道（Slack、email、共用文件）也要算進盤點範圍**，不只看工具權限。

### 單則精選

- **宝玉的提示詞工序：先聊到滿意，再叫 AI 把它寫成提示詞** — 他的流程：跟 AI 反覆對話調到滿意 → 問「**如果其他人也想做類似的東西，提示詞該怎麼寫？中文、簡潔、1～3 段**」→ 用它寫的提示詞重跑一次，有問題再改。示範的印章提示詞裡有兩句值得抄：「**動筆前先列出每個字由哪些部件組成、各放在哪裡**」（先規劃再做）、「**做完先截圖檢查每個字認不認得出，有問題再改**」（把驗收寫進提示詞）。吃瓜影片的提示詞也一樣，結尾是「交付前用 STT 回聽旁白、抽幀檢查、檢查重複鏡頭」。🧠 這就是熱點卡 1 的個人版：**驗收寫在提示詞最後一行**。🏢 talk-prep 的素材包提示詞可以照這個格式改。｜@dotey ｜[印章提示詞](https://x.com/dotey/status/2107286262688231469)｜[怎麼讓 AI 寫提示詞](https://x.com/dotey/status/2107356291794342105)｜[吃瓜影片提示詞](https://x.com/dotey/status/2106144184449085474) ⚡
