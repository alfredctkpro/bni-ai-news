## 🟢 工具用法

### 🔥 熱點卡 1 — 免費午餐結束：最強模型太貴到沒人用，「哪個活派給誰」變成成本槓桿
🔥 6+ 人在談（Drew Breunig／Simon Willison(FT+Ramp)／Braden Hancock via swyx／宝玉×2／AI Engineer）

- 🏢 **這是你「投入 ROI 判準＝cost per finished task」缺的最後一塊實證**：判準不再是「用最強的」，而是「這一段活的最低可接受模型是哪個」。ctkpro 報價與交付成本可以據此重算。
- 🧠 該練的能力從「會用最強模型」變成 **模型路由（routing）＋ harness 設計**——這才是拉開差距的地方。
- **關鍵數據（Ramp AI index，7 月 Anthropic 模型支出佔比）**：Opus 4.8 **28.0%**、Sonnet 4.6 8.3%、**Fable 5 只有 8.0%**、Opus 5 3.5%。最強的模型因為太貴，實際採用率輸給次強一大截。（同文：Anthropic 年化營收升到 $65bn，5 月還是 $47bn；6,000 家客戶年花 $100k 以上）
- **轉折點的說法（Drew Breunig，本期最值得記的一句）**：「Fable 之前，花太多時間改善你的 coding harness 或 context 策略是很蠢的——反正新模型會用同樣的價格（甚至更便宜）幫你把問題蓋過去。但 Fable 來了。它很驚人，可是成本太高，而 Opus 就夠好了（5.6、K3、甚至 GLM 也是）。**所以我們開始思考什麼活該去哪裡。**」
- **同一週的旁證**：Braden Hancock「這個月感覺是 harness month，大家靠優化 harness 在一堆 benchmark 上拿到更快更便宜的進步」；AI Engineer 世界博覽會「AI Architects / AI Factories」track 的主論點——**the model is the easy part of the factory**。
- ⚡ **可立刻抄的落地招（宝玉，附提示詞）**：「Fable 預設用 high 就夠，然後讓它主要負責編排、驗收，這樣最經濟實惠。」提示詞原文：
  > 注意你的主要任務是分析、編排和驗證，具體任務盡可能交給 subagent（Opus 或 Sonnet）去執行。自己只做需求澄清、方案拆解、任務分發和結果驗收，實現類工作（讀大量代碼、寫代碼、跑測試、批量修改）一律用 Agent 工具派給 subagent 執行。
  >
  > 他另補一條路由經驗：**「Codex 做 UI 不行，還是得 Opus 或者 Fable」**——分工要看活的種類，不是一律高階。

### 🔥 熱點卡 2 — 新瓶頸是「人的認知容量」，不是產出速度（本期最該進圓桌的一張）
🔥 5+ 人在談（Simon Willison／宝玉／響馬／Anthropic 官方創業指南／Databricks）

- 🏢 **直接是 ctkpro 團隊設計與 P1-P4 拍板節奏的理論支點**：你「架構師」的定位在這裡拿到了名字——Brooks《人月神話》的**外科醫生模式**，AI 時代第一次變得可行。也直接回答「為什麼不能一個人全包」。
- 🧠 個人上限不在打字速度、在**能同時在腦中維持多大的系統一致模型**——這是 Vibe Coding 終局境界要定案的那把尺。
- 👨‍👩‍👧 小孩該練的稀缺力被指名了：**定義問題 ＋ 判斷力 ＋ 維持整體一致性**，不是寫程式的速度。
- **Simon Willison（Talking Postgres podcast 逐字稿）**：「以前一個工程師一天能產出幾百行 production-ready 的碼，200 行已經是非常好的一天，多數日子只有 50-60 行。如果 agent 讓你一天產出 1000 行**除過錯的**碼，那真的是有意義的進步——前提是品質一樣（可維護、有測試）。……那為什麼公司還需要一個以上的工程師？除了 bus factor，答案是**新的限制因素是認知容量**。我可以快 100 倍產出程式碼，但我沒有能力掌握 100 倍的程式碼。所以你還是需要一個團隊，**用來把認知容量做負載平衡**。」
  - 他同場另談 **conceptual integrity（概念完整性，也出自《人月神話》）**：設計良好的軟體沒有意外、剛好覆蓋對的範圍、每個部分都合得起來。有了 coding agent，你想到一個功能、跑一個 prompt、五分鐘後功能就有了——**於是你的軟體開始往奇怪的方向長出小凸起**。主持人的比喻：**溫徹斯特神秘屋**（140 個房間、樓梯通到天花板）。
- **宝玉（獨立寫出同構結論）**：從康威定律講到《人月神話》的外科手術團隊——把系統設計決策集中在一個人腦中，其他人全是支援角色，溝通路徑從網狀變星型。當年沒流行是因為「外科醫生級人才稀缺」＋「一個人掌握不了爆炸的複雜度」。**但 Agent 時代 agent 可以當那個支援團隊**：一個能定義問題、有判斷力的人 ＋ 一群 agent ＝ 一個完整的交付單元。
  - **他自己踩的煞車最重要**：「AI 加速了執行，但**並沒有擴大人類工作記憶的容量**。一個人能用 AI 更快寫出代碼，但他能同時駕馭的系統複雜度並沒有同比例增長。」→ 所以超大系統仍需分工，只是粒度變成「**幾個外科醫生各帶自己的 AI 團隊、靠設計好的介面契約鬆耦合**」。
  - 他引 Xiaowen 的組織版推論：「個人效率解決『更快完成眼前這件事』，組織效率解決『**省掉哪些不值得做的事**』。把 AI 槓桿交給本來就能定義問題、整合資源的人，他們一天做完過去要協調數週的東西；交給只會執行局部指令的人，只是把一小時縮成半小時，**組織層面看不到任何變化**。」
- **響馬／宝玉的洗碗機模型（ROI 邊界）**：工具化會一路推進到「ROI 低於人力」的邊界就停——洗碗機洗不了異形鍋、燒焦鐵板、精緻瓷器，為搞定最後 5% 要投入比前面 95% 多十倍的錢，不如留一個人。**而且工具越強、行業總產出越膨脹，「縫隙」的絕對數量反而變多**（裁掉 3 個普通洗碗工，最後又請了 2 個處理疑難雜症的）。
- **Anthropic 官方《Claude Code 創業公司指南》**（15 家高增長新創，「10 人團隊打出百人產出」）：ClickHouse 功能交付量 +30%，兩個自製 agent 成為代碼庫貢獻榜第 2、第 3 名；Omni 工程生產力 2-3 倍；Clay 缺陷分流 100% 自動化（agent 還會在初步排查後提修改建議）；Artemis Security 每週交付超過 6,000 個 PR。
- 多方觀點：Simon 從「個人上限」切｜宝玉從「組織形態」切｜響馬從「ROI 邊界」潑冷水｜Anthropic 從「已達成的案例」推｜Databricks：角色正在往「決定要建什麼、系統怎麼組」的高層決策移動。

### 🔥 熱點卡 3 — Claude Code / Claude 平台一週更新（含一個直接省 token 的開關）
🔥 Boris Cherny／宝玉×4／歸藏／ClaudeDevs

- 🏢🧠 你是重度使用者，這批全部可在 10 分鐘內設完：
- ⚡ **`crossSessionInbound: "refuse"` 寫進 `~/.claude/settings.json`** ——上期你已經被這功能咬過，這是解法。宝玉描述症狀：跨 session 訊息通知**會喚醒所有早已結束、沒有 cache 的歷史 session，token 一下子消耗得飛起**。本期最直接省錢的一招。
- ⚡ **output style 改 `Concise`**（`/config` → 輸出風格）：先給結果、回應變短，但仍給完整細節。歸藏：「原來那個又臭又長的，真太噁心了。」
- ⚡ **Claude Code 內建 `/design`（Claude Design）**：原型與設計一體、**不依賴 Figma**（也可導入 Figma 稿），產出是 **React + 模擬 data、可直接互動**，agent 容易還原成程式碼。宝玉實測：「比在網站上用方便多了，和本地專案打通了，不用來回切換。」
- ⚡ **auto mode 可以用白話設定**（Lydia Hallie）：classifier 是一個**獨立的模型**在逐個動作審查——所以你可以用自然語言描述「什麼能自動、什麼要問我」。
- **平台面（GA 了）**：Computer use、browser tool、**Skills API**、Files API 在 Claude Platform 正式可用——可自動化沒有 API 的應用、用**版本化的 skills 與可重用 files** 建 Claude Managed Agents。另：Claude Security scans 改跑 Mythos 5（Enterprise public beta）。
- **設計心法（宝玉，反直覺）**：「**靠 Skill 差別不大**。要設計得沒有 AI 味，最重要的是**人的審美**；其次是模型（GPT 做不好設計，Claude 強很多）；最後是**個性化的 design system**——一套設計規範和元件，而不是一堆『不能怎麼設計』的規則。」配套的具體招（Hallmark design skill，25.8k star）：把 AI slop 的套路全列成「別這麼幹」餵給模型；**餵參考圖和截圖**；提示詞越長越具體越好；**用便宜小模型迭代**（GLM 5.2 效果跟 Opus 幾乎分不出來但快很多）。

### 單則精選

- **驗證，才是新瓶頸——「逐行看 code 從來就不是最有效的驗證方式」** — 🏢🧠 Simon Willison：「有效使用 coding agent 所需的關鍵技能，是能**有把握地指示它怎麼改、再有把握地驗證那些改動確實照正確方式落地**。有時這代表逐行審查，但還有別的方法達成同樣目標。」geoff 從另一頭補上代價：AI 是**時間壓縮裝置、是點子的 fuzzer，讓你「快點錯、便宜地錯」**，但「限制明確就在驗證上——我有一個幾乎 1:1 重現某知名 devtools 產品的東西，好到可以上市，但要對客戶負起責任，就得有能**快速回應/排查缺陷**的工具鏈，而那個 codebase 是一週生出來的、我對它的細節近乎零理解」。 ｜ Simon Willison／@GeoffreyHuntley ｜ [Simon](https://simonwillison.net/2026/Aug/22/more-than-just-code-review/)｜[geoff](https://x.com/GeoffreyHuntley/status/2090713249721254047)  🔗 建議 /ingest（併你懸著的「review 成本反轉」）

- **Gene Kim「Kill My SaaS in one weekend」實戰結果：68 人完賽，他自己殺掉了兩個 SaaS——但也自曝軟體工廠做出來的東西爛到讓他生氣** — 🏢 **直接對你待決的「SaaS 訂閱盤點／自建評估」**。正面：他不只殺掉那個 $40K/年的投稿（CFP）SaaS，連相鄰的、用了十年也很喜歡的會議排程 SaaS 也一起殺了。反面（更有價值）：他坦承自己只認真顧了「投稿審查流程」那一段（因為那是他最有怨氣的地方），排程那段只是照 swyx 的 eval 生出來——結果「我把排程頁面叫出來時心一沉、我生氣了：它給了 24 個**預先填好**的時段，每一個都要主辦人手動取消。這是對使用者的終極『去你的』——24 次無腦點擊。」**→ 自建的真成本不在 token，在你的注意力配額；你沒認真顧的那一段一定會爛。** swyx 說下週公布完整結果，而且他還有下一個 SaaS 要殺。 ｜ Gene Kim／@swyx ｜ [原文](https://x.com/swyx/status/2090538352587993175)｜[swyx·下週公布](https://x.com/swyx/status/2090908959590740033)  ⚡ ⚠️

- **agent 權限治理正在被大廠平台化——你的時間窗又窄了一格** — 🏢 三個同週訊號：①steipete 在 Berkeley「Agentic AI Summit 2026」（現場約 5,000 人、線上約 10 萬）講的題目就叫 **"No Doors for Agents"**；②OpenClaw 下一版在做 **code mode guardian approval**（在手機網頁 UI 上批准 agent 的 PR）；③**Anthropic 要改資料保留政策**（Boris Cherny：Mythos 級模型需要額外安全措施、企業要滿足自己的隱私與合規規則，**客戶擁有並控制自己的資料、Anthropic 一點都不留存**，今秋上線）。→ **佐證你已經調整的方向是對的：不做通用權限平台，做「客戶 tribal knowledge → 可稽核 policy」的落地服務**——因為「門」跟「批准 UI」大廠自己在做，剩下無法被平台吃掉的是**每家客戶自己的規則怎麼寫成可稽核的 policy**。 ｜ @steipete／@bcherny ｜ [No Doors for Agents](https://x.com/steipete/status/2090898421108605078)｜[Anthropic 資料保留](https://x.com/bcherny/status/2090537902912815536)  ⚠️

- **「別叫我用你的 agent——給我 MCP 或 CLI，我用我自己的 agent 去用你的東西」** — 🔥 3 人在談（Gergely Orosz／宝玉／Ali Spittel）。🏢 **這是產品/接案的介面決策題**：Gergely「太多廠商沒搞懂這件事。我只用一兩個 agent。除非你是前沿實驗室，我大概不想用你的 agent，抱歉。」宝玉附議：「每個人常用的 agent 就那麼兩三個，最佳形式是這些服務或 App 提供 MCP 或者 CLI，從 agent 裡面去存取。」→ 對 ctkpro 做客戶系統：**「在產品裡塞一個內建 agent」很可能是投錯的力氣，開 MCP/CLI 才是**。 ｜ @dotey／@steipete ｜ [宝玉](https://x.com/dotey/status/2091425749739643124)｜[Ali Spittel](https://x.com/steipete/status/2090990783260479533)

- **「可擴充軟體」範式：穩固可問責的核心 ＋ 讓使用者用 LLM 安全擴充** — 🏢 Jeremy Morrell 的假說：**LLM 讓「寫擴充」的成本暴跌，現代 sandbox 原語讓部署成本與安全邊界同時成立** → 把 app 做成一個紮實、可問責的核心，讓使用者安全地往各個方向擴充，「我們可以給使用者超能力」。Simon 同期實測了具體工具：叫 Fable 5 把 smolmachines/smolvm 當成跑不可信 Python/JS 的沙箱測到底（限 RAM/CPU、防 `while true`、無網路、只給指定檔案）——過程中 agent 發現 Claude Code for web 容器沒有 /dev/kvm 跑不動，**自己改走 GitHub Actions runner** 把測試跑完。→ 這是**投資戰情室**要「從 demo 變成真服務決策的系統」時的一條架構路：核心你顧、策略讓使用者自己擴。 ｜ Simon Willison ｜ [Jeremy Morrell](https://simonwillison.net/2026/Aug/19/jeremy-morrell/)｜[smolmachines 實測](https://simonwillison.net/2026/Aug/19/smolmachines-untrusted-sandbox/)
