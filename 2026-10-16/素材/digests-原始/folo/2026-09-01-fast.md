## 🟢 工具用法

### 🔥 熱點卡 1 · 7 人在談 ｜ 「驗證系統」才是 AI 寫程式的真正瓶頸 🔗⚡
**綜合**：本週最一致的訊號——AI 把「生成程式碼」的成本壓到近乎零，於是**品質的方差被數量放大**（以前一天幾百行，現在幾千幾萬行）。多位第一線者同時得出同一結論：**能不能給出「明確方向 ＋ 可自動驗證的回饋迴路」，決定 AI 產出是資產還是負債**。Paul Dix（InfluxDB）以「AI 寫了 1M LOC、再花兩個月打磨成可靠軟體」當實例；宝玉把它公式化成 **「決策（方向）＋ 高品質回饋（糾偏）」**，並強調自動化測試是少數能「自動給 AI 回饋」的場景，寫作等場景則仍需人給方向。

- 🏢 **ctkpro**：直接背書你 Vibe Coding 大改版把 **P2 = 驗證/TDD** 排在 P3（PR/Git）之前的順序——沒有 P2，後面的並行、跨平台都在放大爛產出。P2 的 demo 驗收標準可以直接借用「修 bug 必須同步補測試覆蓋」這條。
- 🧠 **me**：你該練的不是更會下 prompt，是**設計 eval / 基準線**（呼應你 pending 的「私有 eval → cost per finished task」）。宝玉那句「不一定要手搓提示詞：整理好測試資料集、設好基準線、反覆測試並給 AI 有價值的回饋，AI 寫的會比人寫的好」＝把 prompt 工程升級成 eval 工程。
- 👨‍👩‍👧 **family**：孩子端的對應版本＝「做出來不稀缺，看出哪裡不對才稀缺」（見單則 · 品味）。
- **多方觀點**：@GeoffreyHuntley 引 Paul Dix 力挺「verification system + proper direction」｜@simonw 補「1M LOC 那件事的重點是後續兩個月的打磨」，語帶保留｜@dotey 拆成「方差變大／決策＋回饋／模組劃分仍是傳統軟體工程」三推｜另有人提「越資深越不敢放手，真正放手反而發生在自己不熟的領域」＝這是心理障礙不是技術障礙。

## 🟢 單則精選

- **AI 做 PPT 的正解：別讓它「操作 PowerPoint」，要讓它「生成」** — 宝玉的實作心得：用 AI 去操作 PowerPoint 這條路本身就不 AI Native，做出來不好看；AI 擅長的是生成（HTML/圖），而非模擬人手拖拉版面。🏢 **直接打你每週的 BNI／對外簡報與 `~/ctkpro-slides` 工作流**——若你現在還在讓 AI 產 pptx，這則是換路線的訊號；也可回頭校準 talk-prep agent 的配圖產法。🧠 一般化的原則：**選任務形態時，選「AI 的生成長項」而不是「模擬人類操作」**。｜ @dotey ｜ [原文](https://x.com/dotey/status/2094466904828068086)　⚡

- **定期刪掉你的 AGENTS.md 與 skills，尤其在模型改版之間** — @GeoffreyHuntley：大多數人不懂的一件事是**該常常刪掉 agents.md 和 skills**，特別是跨模型版本時——舊模型的補丁會變成新模型的枷鎖。🏢 你 thinkr／各 repo 的 CLAUDE.md 與 skills 已累積很厚（MEMORY.md「缺汰換機制」正是同一病），這給了一個具體節奏：**每次主力模型換版＝一次 prompt 資產大掃除**。🧠 呼應你自己那條「記憶是算力的函數」的尺。｜ @GeoffreyHuntley ｜ [原文](https://x.com/GeoffreyHuntley/status/2094270370635505969)　⚡🔗

- **讓 AI 跳出既定框架的提問法：「若跳出當前架構，基於目標重新設計會怎麼做？」** — 宝玉原本抱怨 AI 難跳出既有框架，換了寫法後有效：不要問「怎麼優化這個流程」，而是**先錨定要達到的目標，明確要求它拋開現有架構重新設計**。🧠 這是可立刻加進你既有工作流的一句 prompt pattern（尤其 CloudFlare 專研、Vibe Coding 各 Phase 的 retro）。🏢 用在客戶方案評估時，能逼出「不是把現況加一點 AI」的替代方案。｜ @dotey ｜ [原文](https://x.com/dotey/status/2092826289841299636)　⚡

- **判斷一家公司是不是 AI Native：看流程是圍繞「人」還是圍繞「Agent」設計** — 宝玉的判準：AI Native 的關鍵是 **Agent 是執行主體，人負責定義問題與驗收**；只是在原有流程裡加一點 AI，那不叫 AI Native。🏢 **這句話幾乎是你「架構師之問」的外部版**——可直接當 ctkpro 內部教育訓練與客戶診斷的一把尺（也是接案時的差異化話術）。🧠 對照你的自我定位「讓人才加速成長的系統的架構師」，這則是把它落到流程層的具體判準。｜ @dotey ｜ [原文](https://x.com/dotey/status/2093714239718351350)　🔗🏛️

- **Anthropic 發布「AI 原生 SDLC 實施指南」（Plan/Design/Build/Test/Deploy/Maintain 六階段）** — 來自 Anthropic Applied AI 團隊日常實踐，講怎麼把 Agent 接進軟體開發生命週期的每一階段。🏢 **可當你 Vibe Coding 五 Phase 的官方對照組**：拿它逐階段比對你自訂的 P1–P5，補漏（尤其 Deploy／Maintain 兩段你目前較薄），也是交團隊時的權威背書材料。｜ @xiaohu 轉述 ｜ [原文](https://x.com/xiaohu/status/2092127063910342799)　⚡🔗

- **Warp 如何讓 Agent 自我進化：解的是「Skill 的演化問題」** — 宝玉讀 Anthropic 官方文《How Warp builds self-improving agents on Claude》後的筆記——重點在**讓 skill 隨使用回饋自動迭代**，而非人工手動維護 skill 檔。🧠 這正面接上你「常刪 skills」那則的另一半：一邊汰舊、一邊讓它自己長。🏢 若要把 Vibe Coding 交給團隊，skill 的自我演化機制決定它會不會在三個月後腐爛。｜ @dotey ／宝玉的博客 ｜ [推文](https://x.com/dotey/status/2093539751127040157)｜[部落格全文](https://baoyu.io/blog/2026-08-28/warp-self-improving-agents)　🔗

- **AI 時代最稀缺的能力是「品味」：做得出來不稀缺，看得出第一版還差在哪才稀缺** — 一個人幾小時就能做出過去需要團隊數月的東西，技術門檻塌了；**拉開差距的變成「能不能拒絕一個已經可用、但沒有主張的答案」**。👨‍👩‍👧 **這是⑥教育定標的正中心**——「該培養什麼能力」的答案：判斷力、審美、敢說「這樣不夠好」。建議帶進 9 月的 family 圓桌（第 3 個週五）。🧠 你自己的版本＝驗收標準（`/goal`）寫得夠不夠狠。｜ @xiaohu ｜ [原文](https://x.com/xiaohu/status/2094290449309778368)　🏛️🔗

- **避雷：現在別開 Codex 的 "locked use"，會把你鎖在自己的 Mac 外面** — @swyx 親身踩雷 PSA：該功能依賴 macOS 尚不穩定的特性，實測導致完全無法登入自己的機器。🧠 純避雷，但成本很高（工作日直接報銷），值得記一筆。｜ @swyx ｜ [原文](https://x.com/swyx/status/2092492963435946494)　⚡
