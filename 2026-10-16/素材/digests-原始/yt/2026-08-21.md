## 🟢 工具用法（①⑤）

### 1. 省 Token 三動作＝清理「AI 時代的技術債」 ⚡
**Gary Chen（核心⭐）｜[AI 額度老是不夠用？三招省 Token 的實戰方法](https://www.youtube.com/watch?v=d4329xvSDK4)**

- 🏢 直接降低 ctkpro 每個交付案的 API 成本；🧠 這支把「為什麼 AI 聊到後面會變笨」講清楚了——**不是模型退化，是雪球 context**。
- Context 四層：①系統與專案規則（system prompt、`CLAUDE.md`、git 狀態）②**工具說明（含所有掛載 MCP 的參數描述，光清單每次就吃幾千 token）**③對話歷史 ④外部檔案與執行日誌。
- **兩個常見錯招都沒用**：把 prompt 寫短（比例微乎其微）、換小模型（來回重試燒更多）。
- 有效招：換任務就開新對話／用 edit 或 rewind **抹掉錯誤產出**（不要在後面補「我剛打錯」）／關掉當下用不到的 MCP／先搜尋再餵／**把結論整理成 Markdown 開新對話**（別全靠 auto-compact，那是有損壓縮）。
- 🔑 **Prompt Caching 命中＝1 折**（Opus 5 輸入 $5/M → cache read $0.5/M），壽命約 1 小時。⚠️ **中途換模型、改 thinking effort、開加速模式，都會讓快取全部失效重算。**
- ⚠️ **與上週行動項衝突提醒**：上週決定「effort 從高檔降 medium」——這支告訴你**要降就一開始降，跑到一半改會炸掉快取、反而更貴**。
- ⏱ **值得看完（22 分）**。看不完就看「三個核心動作」＋最後兩個自問。金句：「省 token 省下的不只是錢，是給 agent 一個乾淨的 context。」

### 2. Hooks＝把「提醒紙條」升級成「自動門」 ⚡🔗
**Gary Chen（核心⭐）｜[Claude Code 必學設定 Hooks，完整教學一次搞懂](https://www.youtube.com/watch?v=rLNGSDYkK-w)**

- 🏢 **這是 agent 權限治理最便宜的第一步**，不用等平台商、今天就能上。
- **核心區分（本期最重要的一句話）**：`CLAUDE.md` ＝提醒紙條，**靠模型自己判斷要不要遵守**；Hook ＝ **deterministic**，由 Claude Code 軟體層強制介入。「不想承擔被 AI 忘記的風險」的事，就該做成 Hook。
- 三層：**Event**（何時）→ **Matcher**（攔哪個操作）→ **Handler**（做什麼）。31 種 Event（Codex 只有 11 種），入門記 4 個：`SessionStart` / `PreToolUse` / `PostToolUse` / `Stop`。Handler 五型：`command`／`http`／`mcp_tool`／`prompt`／`agent`（**Codex 目前只真的執行 `command`**）。
- 現成案例：Superpowers 用 `SessionStart` **強制載入 Skill**（對付 skill 載入的隨機性）；Claude-Mem 用 `UserPromptSubmit` 攔提問**去背景資料庫撈記憶再塞回去**（解跨對話失憶）；Matt Pocock 用 `PreToolUse` 擋 `git reset --hard`；`PreCompact` 在壓縮前**先保存關鍵決策**避免漏掉。
- 兩個長期穩定的檢查：①Matcher 縮小範圍、Handler 再細判 ②**Stop Hook 一定要有結束條件**（他的做法：連續三輪沒過就停、交人工），否則會無限退回。
- ⏱ **值得看完（22 分）**，是本期最可操作的一支。Gary 自己用 `Stop` event 呼叫 Codex 做 cross-model peer review。

### 3. ⚠️ 8/14 起 Claude Code 預設 auto mode——而且「加一條規則」會把 65 條內建防護整套換掉 ⚡⚠️
**YAHA学堂（核心⭐）｜[Claude Code 加1行代码防护全废？我实测65条默认规则消失](https://www.youtube.com/watch?v=XW2pikSTxPg)**

- 🏢 **這條是本週唯一「今天就該去查你自己機器」的**；🧠 也是理解「平台商怎麼做 agent 治理」的活教材。
- **陷阱**：在 `soft_deny` 加一條自訂規則 → **整套內建 65 條防護（刪資料庫、force push、生產環境部署、拿走密鑰、下載腳本直接執行）全部變成預設放行**，不報錯不警告。正解是**在 `soft_deny` 裡加一行 `$defaults`**。查法：`claude auto-mode critique`（30 秒）；`auto-mode defaults` 印出廠設定、`auto-mode config` 印你這台實際生效的合併結果。
- **8/14 起 Pro/Max/Team 新開的會話預設 auto mode**：不再每步彈權限框，改成**每個 tool call 送進一個獨立分類器**（另一個 Claude，只看「這條命令危不危險」、不參與寫程式、不看整段對話 → 不會被聊著聊著帶偏）。
- 數據：2026 年 6 月 **49.5% 活躍 CLI 使用者手動加過 Bash allow 規則，其中 5% 直接放行任何 shell 命令、43% 設 `Bash` ＝實際等於全開**。
- ⚠️ 兩個 `allow` 別搞混：`permissions.allow` ＝門口保安（看一眼放進來）；`autoMode.allow` ＝裡面審查員手上的豁免清單。**分類器不讀專案裡的 `settings.json`**（因為 clone 陌生專案就能塞規則提權）；`CLAUDE.md` 只能加約束、不能放行。
- 🧠 **作者最值得抄的一句批判**：Apollo 紅隊漏判率 12%→7%，「但這個對照組是**累趴下的人類**，不是認真審查的人類。97% 通過率是現實沒錯，但這是拿差的比更差的。」
- ⏱ **必看（8 分，短）**。看完立刻跑那一行。

### 4. 忙碌老闆的 Claude Cowork 三件事：靜態脈絡 → Skill → 排程 ⚡
**Simon Scrapes（核心⭐）｜[The Only Claude Cowork Setup Busy Entrepreneurs Actually Need](https://www.youtube.com/watch?v=BMEaJTl3Vo0)**

- 🏢 直接對口 ctkpro 的交付一致性與「知識留在人腦裡」問題。
- **鐵律**：同一段資訊你在 chat 打過**兩次以上**，就該變成檔案並在 `CLAUDE.md` 裡引用。三個檔每家公司都該有：①**brand voice（每個平台各一份**——LinkedIn/email/社群語氣不同）②**visual identity**（顏色、字體、design tokens JSON；用 Claude Design 的 design system 產，**別用官方 theme factory**——太基本且大家都在用）③**business facts / ICP**。
- Skill 的三個捷徑：用官方 skill-creator／**直接錄製操作過程自動生成**（4 分鐘錄出 60 步驟的複雜流程）／用現成的——**Anthropic 官方「small business」plugin 內含 31 個 skill**（invoice chase、close month、**margin analyzer：哪些案子/客戶真的賺錢**、Canva creator），設定裡 plugins → browse 就能裝。
- 排程任務**可在雲端跑（不用開電腦）**、手機收通知。⚠️ **雲端排程碰不到本地資料夾** → 靜態脈絡要放 Notion/Google Drive 用 MCP 接。
- ⏱ 值得看完（15 分）。**先去裝 small business plugin 試 margin analyzer**，這是最快能驗證的一項。

### 5. 🔑 接了 connector ≠ Claude 知道你的資料——實測只讀到 0.5%–5% ⚡🔗
**Tiago Forte｜[I Connected Claude to My Entire Life (Here's What Broke)](https://www.youtube.com/watch?v=4yQw6N-lLPA)**

- 🧠 **這是本期對 thinkr／第二大腦最重要的一支**；🏢 也直接影響「交付給客戶的 AI 分析可不可信」。
- **權威假象（illusion of authority）**：接上 connector 後大家假設「Claude 知道我的 Notion 了」——**它其實是在取樣偵察**。他實測跨多個 connector，實際讀到的內容**只佔全部的 0.5%–5%**。
  - **Gmail connector 預設只讀主旨／寄件人／收件人／標籤＋一小段摘要，不讀信件全文**（除非你逼它）。
  - **Google Drive connector 明顯偏好近期檔案**（近幾天/週/最多幾個月），多年前的基本不看。
  - 👉 結論反直覺：**有 connector 反而更需要查證來源，不是更不需要。**
- 五個可以直接抄的做法：①**先要它給「搜尋計畫」給你核准**（去哪找、判準是什麼）再讓它答 ②**要求所有回答附連結與引用——內部文件也要** ③先要它總結「整體搜到了什麼」再給那一個答案（廣的結果好稽核，單一答案是黑箱）④**要它主動標出落差／衝突／不一致**讓你仲裁 ⑤**在 prompt 視窗取消勾選用不到的 connector**——省 token ＋ 縮小 lethal trifecta 攻擊面。
- 權限設定慣例：read-only tools → always allow；**write / delete / interactive → needs approval**。
- 方法論可抄：資料盤點**從信用卡帳單開始列**（付錢的＝真的在用的），再掃電腦/手機/瀏覽器書籤；選 connector 的判準**不是軟體先進不先進，是那個工具裡的資料夠不夠深、夠不夠久**。
- 🧠 一個很硬的自我校準示範：他行事曆顯示「健康與健身」時數第一，但**行事曆只知道你排了什麼、不知道你做了什麼**——他拿健身 app 的 99 次實際紀錄回頭修正（承諾 183 次、實際 99 次，但每次 90 分而非 60 分 → 反而多 38 小時 → 結論是「**少去幾次但待久一點更划算**」）。最後 Claude 指出他「工作吃掉最好的自己、家人拿剩下的」這個長年自我批評**與資料矛盾**：工作量大，但**它是繞著錨點彎，不是錨點繞著工作彎**。
- ⚠️ 他親自潑的冷水：**那些 V1 產出物都還需要你**——「社群上說接好 connector 就能自動運行你的人生，我實測不成立。」
- ⏱ **值得看完（35 分）**，是本期唯一「看完會改變你怎麼用 Claude 讀自己資料」的一支。

### 6. Compound Engineering：一個工程師＋複利系統，打敗用 AI 但不複利的整個團隊 🔗⚡
**AI Engineer｜Kieran Klaassen（Every / Cora）｜[The Era of Compound Engineering](https://www.youtube.com/watch?v=_ehJyfHg1Vk)**

- 🏢 **這是「模型 × 工程系統是乘法」那條 ingest 待辦的最佳單一素材**；🧠 也是 thinkr 這台引擎的外部同構驗證。
- 開場：「**我今年一行程式碼都沒寫過**，甚至沒看過大部分。但我一個人維護數千人信任的 email 產品。」
- **瓶頸遷移史**（每一階段被解掉就往上移）：爛程式碼 → 計畫品質 → 決定要做什麼 → **重複自己**（→ 建記憶系統）→ **judgment 與 taste**。「實作基本上解決了，沒解決的是我們的判斷與品味。」
- **人-AI 三明治**：人是麵包（頭尾），AI 是中間。**腦只開在兩端**——brainstorm（決定做什麼）與 polish（**不是 QA，是拉高標準**）。
- **50/50 規則**：50% 時間做功能，**50% 時間教系統**（做錯的地方能不能學起來）。
- 反直覺：把知識存在 repo 當 solution documents，**長期反而更省 token**（不用重新 research、不用 review、不用修正——答案已經在 token 裡了）。
- 金句三連：「**我的大腦是固定的，AI 不是**」／「**document the thinking, not the code**」／「**下一個功能應該因為你做了這個而更容易，不是更難**——一般的軟體工程是反過來的，我們要把它翻轉。」
- 判斷「到位了沒」的訊號：**你按下去它跑三小時、結果總是好的，那你就到了。**
- 🔗 plugin 開源、可裝在 Claude Code / Codex / Cursor。
- ⏱ **必看（18 分）**，本期第一名。

### 7. 「Prototyping as Leadership」：行程滿檔的 CTO 一週出 2-10 個 PR 🔗⚡🏛️
**AI Engineer｜Hursh Agrawal（The Browser Company CTO）｜[Prototyping as Leadership: How a CTO Ships with AI Agents](https://www.youtube.com/watch?v=bdHaOXZOhcM)**

- 🏢🧠 **這支的處境跟 Alfred 幾乎一模一樣**：一週 15+ 個固定會議、7 個直屬、家裡有幼兒、只工作 40-50 小時，卻穩定一週出 2-10 個 PR。**直球挑戰「架構師之問」**：不是「該我親自做嗎」，而是「**不親手做，我就沒有能力判斷與傳達**」。
- 為什麼領導者非親手 build 不可：①**每 3 個月換一代前沿模型，不親手用就摸不出輪廓**（Twitter 上噪音太多，模型好在哪只能自己撞）②就算你建立了直覺也**很難口頭傳給沒玩過的人** → **做一個 prototype 給他們看，比每三個月說服人快太多**。
- 為什麼領導者適合：**你有全公司最多的 context，所以你每 token 的操舵影響力比 IC 高**；委派技能可直接轉移到 agent（設目標、給脈絡、check-in、甚至 coach）；**模型執行力強但判斷力仍弱**，領導者剛好補那塊。
- ⚠️ **該建什麼／不該建什麼**（引 Julie Zhuo）：內部工具、codebase 園藝、慶祝團隊的 artifact、**vision 原型（最重要）**。**絕對不要接關鍵路徑的工作**——你會被會議跟救火拖走。
- **可直接抄的一天節奏**：早上 1 小時 review 昨晚 agent 的產出 → 白天穿插 steering block → **下午 5 點設定 overnight run**。
- Overnight loop 訣竅：先用 co-work agent（連 Slack/Jira/Notion/repo）**花 20 分鐘研究，產出一段要貼進 Claude Code 的 prompt**（含 trade-off、以前試過什麼、business context）；要它**先寫測試**（事後寫會敷衍）、用 computer use 跑端到端、**拆成 reviewer-friendly 的小 PR**、CI 綠、跑 AI code review skill 再自己修。
- 三種可整晚跑的任務：建功能／**優化 AI 功能**（收 10-30 筆 feedback JSON → 讓它自己設計 eval → 建 harness hill-climb 到分數上升）／**訓練自訂小模型**（BERT PII classifier，給沙箱 AWS 權限、**不給 prod**）。
- ⚠️ 前提是組織鷹架：AI code reviewer、`CLAUDE.md`/`agents.md` 衛生、可信任的 CI、feature flag、prototype branch。紀律：**PR 上去前自己測**、**小而可讀的 PR（你在示範什麼叫「好」）**、**絕不把自己沒讀過的 code 丟給別人 review**。
- ⏱ **必看（15 分）**，本期第二名。

### 8. 停止人工 code review 的判準：PR 上的人類 comment 遞減 → 累積 100 個 PR 🔗🏛️
**AI Engineer｜Itamar Friedman（Qodo CEO）｜[The Last Human Code Review](https://www.youtube.com/watch?v=s-aixZYJG4c)**

- 🏢 **直接對口「review 成本反轉」那條 ingest 待辦**，而且給了可操作的判準。
- 先問：**code review 存在的兩個目的**是①驗證品質 ②**對齊與教學**（senior 教 junior 的最後一道關）。要自動化前先問「這兩件事還能不能做」——第二個常被忘掉。
- **模型不是瓶頸了，context 才是**：他剛從一家頂尖實驗室回來，「code review 的 benchmark 在最近幾代模型上幾乎沒變」。缺的是 tribal knowledge、系統架構、**哪兩個 microservice 的 contract 會撞**、過去三個月的 P0 事故與 root cause 討論。
- 現況：context 散在 `agents.md`／`claude.md`／`skills.md`，各團隊各寫各的 → **缺一層 governance layer**。要建的是 **context lake**，而且**必須同時給人看（可信任、可稽核）和給 agent 看**（他們的做法是 PR 上同時留「引用了哪 4 條規則、違反哪幾條＋連結」給人，跟一段對 agent 說話的留言）。
- ✅ **判準**：導入後**開發者在 PR 上寫的 comment 會越來越少；累積 100 個這樣的 PR，你就知道可以自動化了**。然後才開始加 auto-approve / auto-block 的語意規則（漸進，不是一次到位）。
- 金句：「**如果你出 AI 程式碼的速度已經超過人能 review 的速度，你不是領先問題，你是身處問題之中。**」／「artificial intelligence → **artificial wisdom**」。
- ⏱ 值得看完（15 分）。前 8 分鐘是精華。

### 9. 🏛️ Agent 需要一張「員工識別證」：真實血案兩則 ＋ plan-then-execute 架構
**AI Engineer｜Sarthak Aggarwal（Decawork）｜[IT Admin for the AI Workforce](https://www.youtube.com/watch?v=q-WOjZhOMCA)**

- 🏢 **這支是「agent 權限治理要不要做成 ctkpro 服務品項」那條待決的決定性素材**——同時給了架構、也給了警訊。
- 框架：企業正在經營**第二支勞動力**，「IT 團隊變成 agent 的 HR 部門」（黃仁勳語）。**demo 能跑 ≠ employment readiness**。Agent 的 runtime identity card 要回答：誰是 actor／誰擁有它／它代表誰行動（on-behalf-of）／誰授的權／能用哪些 capability／哪條 policy 管／**多快能撤銷**。OAuth token exchange 形狀對，但**還缺一個 agent identity 標準**。
- 安全的本質變了：**untrusted text can cause a trusted action**。Simon Willison 的 lethal trifecta（私密資料＋不可信輸入＋對外通道）他再補一項＝**action layer**。而「有用的企業 agent 三個都要」——這不是 bug，是產品規格。
- **兩則真實血案**：
  - **EchoLeak**：Microsoft 365 Copilot 的**真實 CVE**（不是玩具 demo）——一封外部 email 進到 Copilot 的 context，zero-click 把資料帶出微軟防火牆。攻擊者不需要憑證、不需要 API key，**只需要寫一封信**。

### 🔥 熱點卡 5 · Opus 5 太囉嗦：官方給了 concise，但真正的解法是 system prompt engineering
**🔥 3 頻道在談 ｜ ⚡ 可立刻試**

- 🏢🧠 上週的行動項「設 output style」本週有了官方新選項＋更深的做法。
- **官方解（30 秒，Chase AI）**：`/config` → output style → **concise**。⚠️ 這只設了「這個專案」；要全域得改 `~/.claude/settings.json`（可以直接叫 Claude「set the output style to concise globally」，但**要確認它真的改到 `~/.claude/settings.json`**）。
- **真正的解（IndyDevDan，核心⭐，本期最紮實的技法）**：「**如果有人跟你說 prompt engineering 已死，完全不用理他。**」大多數工程師只用 user prompt，**system prompt 才是槓桿——因為它會被乘上你的每一個 prompt 與每一個回應**。用 `--append-system-prompt`（append 不是 overwrite），五個可直接抄的 pattern：
  1. **Purpose ＋ 為什麼**（不給角色扮演，就當同事講話：「我們維持 no-BS、清楚、精簡、可行動的關係」）
  2. **正面／負面 pattern 清單**：正面＝「**我永遠先看到你寫的最後一件事，把最重要的放那裡**」「每個事實只講一次」「細節程度要配合任務規模」「**直接挑戰錯誤假設並解釋為什麼**」；負面＝把 `load-bearing`、`worth stating plainly`、`here's the honest truth` 這些口頭禪列黑名單，加上「不要諂媚」「不要裝飾性標題與 emoji」「少用破折號鏈」
  3. **Reference points**：要它給決策 D1/D2、風險 R1/R2、發現 F1/F2 短碼 → **之後你直接說「多談 R6」，不必重述，省掉大量重複 token**
  4. **Hard operational boundaries**：「**只交付被要求的、在被要求的範圍內**」「不要擴散成清理／重構／文件／相鄰功能」「**不要在沒有證據時宣稱完成**」「不要幫我猜未來需求做抽象」
  5. **Aliases**（自訂短碼，像 bash alias）：`SCR`＝simplify, compress, repeat／`ELI18`＝解釋得像我 18 歲／`FOC`＝聚焦在最重要的那件事／`REF`＝用 reference points 重寫。打四個字母就能壓縮一段冗長回應。
  6. bonus **in-context distillation**：把你喜歡的模型（例如 Fable 5）產出的回應**當範例貼進 system prompt 的 do/don't 段**——這是 GPT-3.5 時代就有效、到今天還有效的老技法。
- 金句：「**Claude Code 把 system prompt 大幅縮短，不是叫你別用 system prompt 的訊號**——那是因為模型不用它也能做很多事。但你要它做**特定**的事、用**特定**方式、不燒你的 output token，就必須 system prompt engineering。」／「對很多任務，瓶頸是你我這個開發者，不是模型、不是工具。」
- 🔗 [IndyDevDan: FIXING Opus 5](https://www.youtube.com/watch?v=S_QdQ1G4GlU)（prompt 開源在說明欄）｜[Chase AI: This New Setting Fixes Opus 5](https://www.youtube.com/watch?v=yJM9q0lmGys)
- ⏱ Chase AI 2 分鐘先做掉；IndyDevDan 30 分，**本期最值得投資的 30 分鐘**。

### 10. ⚠️ Anthropic 自曝 186 頁風險報告：三個裂縫，其中一個叫「Agent 集體罷工」

### 11. ⚔️ 兩支唱反調的：「fine-tune 是技術債」vs「不掌握權重就不擁有產品」 🔗🏛️
**AI Engineer｜Dan Bjornn（Lease End）｜[Your Fine-Tuned Model Is Tech Debt: A 50x ROI House of Cards](https://www.youtube.com/watch?v=4loPnxvWWhg)**
**Best Partners TV｜紅杉 Sonya Huang｜[不掌握权重就不拥有产品](https://www.youtube.com/watch?v=Ai20DvMg6uM)**

- 🏢 **這對「自建 vs 外採」的判準，剛好是 ctkpro 給客戶做技術建議時最常被問到的。**
- **反方（Lease End，第一線血淚）**：他們 fine-tune 的意圖分類模型一年帶進 **1200 萬美元營收、50 倍 ROI**——但底下悄悄長出技術債。他稱之為「**鈣化稅（calcification tax）**」：用越久越僵硬。①**被鎖在模型版本**（同一供應商不同版本的訓練資料要求都不同，跨供應商更是天差地遠 → 想升級升不起）②**被鎖在 2024 年的 workflow 架構**（AI 世界跑太快，他們光維持運轉就沒餘力換架構）③修一個 bug 要**一整週**（收集案例→合成→標註→人工驗證→fine-tune→**打地鼠般的回歸**），所以他們只好**按「客戶痛到什麼程度」排自己的 bug、先攢夠問題量再一起修**。
  轉折：用了 Claude Code 之後他發現「**我們從來不用換模型，只換 skill、資源、context**」。改成 skill/tool/resource 架構後：發現問題 → 改 system prompt 或 skill → 在既有 curated set 上驗證 → **上傳 MD 到 S3 即部署**，**從一週壓到不到一小時**。
  結果：**每則訊息成本變高，但總成本下降**（維護時間大減）、**準確率反而更好**、vendor lock-in 解除。
  結論：「**只有在你真的無法呼叫前沿模型時才 fine-tune。就算那樣，你的決定還是得先贏過那筆鈣化稅。**」
- **正方（紅杉 Sonya Huang）**：「戰場已經變了，競爭不再是應用層之爭，是**智能層之爭**。**不掌握權重，就不擁有產品**」（化用 crypto 的 Not your keys, not your coins）。四個驅動力：成本（規模到了以後 API 是線性成長且不可控）、速度（垂直領域小模型更快更好）、性能（**開源基座＋你的專有資料做後訓練，能贏過通用閉源 API**）、**掌控命運**（供應商漲價/改介面/停服；資料合規）。
  ⚠️ 但她自己先澄清：**這不是非黑即白**——重點是「**你要有能力界定清楚：哪些能力必須握在自己手裡、哪些可以外採**」，用四個維度（成本／速度延遲／性能／**你的專有資料到底有多獨特**）畫出那條線。四步路徑：①先做戰略界定（**這首先是商業決策，不是技術決策**）②組一個**小而精的專屬研究小組**（⚠️「不要指望原來的平台團隊順便把模型這件事幹了」）③建立外界技術可辨識度（發論文/開源/技術部落格 → 招得到人＋客戶相信你真有能力）④明確技術路線圖（**評估標準先訂**、路由器與框架怎麼選、預留往後訓練甚至預訓練走的空間——「不用一開始就蓋百米高樓，但地基要打夠」）。
  一個容易忽略的架構點：現代企業 AI 技術棧是**生產環境 ＋ 開發環境（評估/資料/訓練/演進）兩套並行且打通**——**只顧生產環境的公司，模型上線之後就迭代不動了，效果永遠停在第一天。**
- ✅ **綜合判斷（給 ctkpro 的那條線在哪）**：兩邊都對，差別在**規模與資料獨特性**。**多數接案規模遠不到 Sonya 那條線 → Lease End 的教訓更適用（用 context / skill，不要 fine-tune）。** 但 Sonya 的**「先畫線」思考框架**可以直接搬去問一個更有用的問題：**ctkpro 交付能力裡，哪幾項必須握在自己手裡（不能靠某家供應商）？** 這正好接上熱點卡 3 的第 3 句。
- ⏱ Lease End 那支 12 分，**值得看完**（本期最好的「反悔案例」）。紅杉那支 16 分，只看前 8 分鐘的四個驅動力＋四步路徑。

## 🟤 AI 教育（⑥）

### 13. 知識工作者的五個 AI 工程能力——以及「學徒制斷層」這個沒人解的問題 🏛️👨‍👩‍👧
**The AI Daily Brief（核心⭐）｜[The AI Engineering Skills Map for Knowledge Workers](https://www.youtube.com/watch?v=f40AKMHebrY)**

- 👨‍👩‍👧 這是「小孩該培養什麼」的具體清單；🏢 也是帶團隊、定義「什麼叫做得好」的清單。
- **地基仍然是 domain judgment**（定義品質、辨識取捨、理解後果、**扛決策的責任**）。而且**不是一般的領域判斷，是「你這家組織脈絡裡的領域判斷」**——「就算 ChatGPT 能寫所有文案、做所有素材，我們也不會期待一個沒有行銷經驗的人能規劃並執行好一場行銷活動。」
- **五個新能力**（層層相扣）：
  1. **AI capability mapping**——理解 Ethan Mollick 講的「**鋸齒狀前緣**」（前一分鐘讓你驚豔，下一分鐘犯連最菜實習生都不會犯的錯）。哪些任務配哪種做法（輔助 / workflow 自動化 / 真正的 agentic）、配哪個模型與 effort level、需要多少人監督。**這件事沒人能直接教你，只能自己撞出來。**
  2. **Context and harness management**——context ＝ AI 需要的資訊；harness ＝模型周圍的一切（指令、文件、工具權限、記憶）。**最佳實務 6 個月後一定會變。**
  3. **Problem and product prototyping**——不是要行銷變工程師，但「當每個人都能推 code，很多以前的工作方式會徹底改變」（他的例子：行銷從手動下載各平台報表拼 Excel，變成直接接 API 建 dashboard，省下的時間拿去做判斷）。
  4. **New opportunity identification**——不是問「AI 能幫我做哪部分」，而是問「**現在有什麼是以前不可能或不划算，所以現在該做了？**」他叫這個「**無限 backlog**」。小訣竅：**假設公司給你一組工程師隨你差遣，你會做什麼？**
  5. **Rapid new skill acquisition**（meta skill）——不是半年一次的教育訓練，是持續的過程。
- ⚠️ **他點出但還沒解的問題（本期最值得帶進 family 圓桌的一題）**：**如果資深的人直接用 AI 做掉了年輕人以前做的事，下一代的 domain judgment 從哪裡長出來？**
  他提三種 judgment 來源當線索：**personal**（自己內化的標準與模式辨識）、**borrowed**（跟資深協作、review、共同決策借來的）、**embedded**（**寫進 examples / rubrics / policies / evals 的**，也就是你餵給 AI 的 context）。他猜可能的解是 **AI 從 single-player 走向 multiplayer——核心單位從個人移到小團隊**。
- 💡 **這題對 Alfred 是三層全中**：👨‍👩‍👧 小孩要練什麼；🏢 Wei 現象／TL→EM／「讓人才加速成長的系統」；🧠 你自己的 embedded judgment 就是 `CLAUDE.md` 與 thinking-models。
- ⏱ 主題段從 12:00 開始，值得看完。前 12 分鐘是新聞（Cursor Origin / Anthropic 財報 / Stripe×OpenRouter，見熱點卡 3）。

- **Braintrust：「架構跟著模型更新走，你的 eval 就得跟著架構走」**（AI Engineer, Ameya Bhatawdekar）——模型每次躍進都是 step function 而非增量，所以你不能只是「換個模型」就期待系統變好：**舊系統是為了繞過舊模型的限制而設計的**。要吃到新能力必須重構架構，**而架構一變，evals 就失效了**。從 single call → chain（RAG）→ ReAct loop → multi-agent，每一代的評估單位都不同。值得知道這個框架，但目前 ctkpro 還沒到需要 eval 平台的階段。[連結](https://www.youtube.com/watch?v=nxokqOq1imY)
