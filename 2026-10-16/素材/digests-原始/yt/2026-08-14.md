## 🔥 熱點卡 1 — 「模型 × 工程系統」是乘法：本週最該記住的一條公式

⚠️ 翻盤訊號 · 🔥 5 個頻道從 5 個方向撞同一題（Best Partners TV／AI Engineer×2／IndyDevDan／TGLTommy）

- **🏢 ctkpro**：這是 7/31「軟體不再是護城河」**最直接的續集，而且給了答案**。a16z 那篇原文作者 Peter Ludwig（Applied Intuition 共同創辦人／CTO）的核心式子是：**已部署的 AI ＝ ①模型能力 × ②周圍工程系統的能力**（需求怎麼變軟體、軟體怎麼被驗證、驗證過的系統怎麼部署／監控／改進）。**乘法意味著任一項拖後腿，整體就被拉下來**——而整個產業把資源幾乎全倒在①，②還停在十年前為「季度發布＋上百人整合團隊」設計的體系。他的比喻：**「用上世紀的生產線去組裝最新的晶片」**。
  - 最可直接引用的一句：**「隨著模型在前沿趨於商品化，兩家擁有相同智能水平的公司會產生截然不同的結果——差距取決於它們的工程系統吸收模型能力的速度。智能正在變得無處不在，但把智能轉化為運營的能力並不是。」**
  - 具體數字：一個 benchmark 提升 20% 的模型，團隊往往要花**整整兩季**才能證明它安全可交付。→ **「模型能力的每一次飛躍，只是轉移了瓶頸，而不是消除了瓶頸。」**
  - Applied Intuition 自家實績（Dana 平台，蓋在十年基礎設施上）：工程師搭出 **1000+ 內部應用與 agent**，開發週期提速**約 20 倍**，部署從幾週一次變**每天多次**。金句：**「當構建成本下降一個數量級，值得構建的東西的集合會擴大不止一個數量級。」**
- **🧠 me**：這條公式把 Alfred 的「三宇宙×三層」從**時間軸**（2024 Prompt → 2025 Context → 2026 Harness）補上了**結構軸**——Harness 不是「第三個階段」，是乘法裡那個被忽視的第二項。可當 8/20 演講的**備答素材**（「為什麼你說 2026 是 Harness？」→ 因為①已商品化，勝負全在②）。**不必動已定稿的大綱。**
- **多方觀點**：
  - **Best Partners TV（華文轉述 a16z 原文，最完整）**：上面那套公式與飛輪。
  - **Anthropic Applied AI（AI Engineer 大會，最硬）**：「**Harness 編碼的是「Claude 自己做不到什麼」的假設——而這些假設會隨模型變強而過期**。」實例：Sonnet 4.5 有 context anxiety（快到 context 上限就提早收尾），他們在 harness 加 context reset 去補；Opus 4.5 這行為消失，那些補丁**變成純負擔**（增加延遲、把 cache 亂丟掉）。結論：**「模型動了、harness 沒動，agent 就會退化。」**
  - **OpenAI Codex（同大會）**：整個 Codex harness 是 **Rust 寫的開源專案（Apache 2）**，可當藍圖抄或直接 fork。
  - **IndyDevDan**：「如果你還在糾結用哪個模型，你沒抓到重點。你需要的是**模型堆疊（model stack），不是單一模型**。**組合算力，別挑算力**。」
  - **TGLTommy（未轉錄，僅標題）**：「MIT 最新發現：Agent 泛化能力不在模型，而在 Harness」——同題第五個獨立聲音。

## 🔥 熱點卡 2 — Agent 權限治理：本週同時出現兩套「可以直接抄」的架構

⚠️ 翻盤訊號 · 🏛️ 建議進圓桌（直接對應 MEMORY.md 待決「agent 權限治理要不要做成 ctkpro 服務品項」）

- **🏢 ctkpro**：8/13 健身房事件之後你記下的判斷是「公開痛點、賣方仍少」。**本週這個空窗被兩個第一線團隊同時填上了——而且填法一致，這代表它已經是可交付的標準架構，不是實驗。**
  - **OpenAI 的做法（Codex `auto review`）**：不是「全開／全問」二選一。當 agent 想escalate（例如刪檔、對外網路呼叫）時，harness **另外開一個 auto-review 子 agent**——這個子 agent **只有讀取權限、且不准再開子 agent**，餵給它的是：使用者授權情境、風險分類法、對話 transcript ＋ 實際要跑的 tool call，讓它判「**使用者授權程度 × 這個動作的影響**」再決定放行。他們的設計目標很明確：**把「難以預測、長時間跑」的動作自動放行，但把資料外洩擋在外面**。他直白講原因：模型變強了，但你用 prompt 逼它「高 agency」時，它可能把「寄檔案給某人」理解成「附件失敗就上傳到公開檔案分享」。
  - **a16z 那篇（安全攸關系統）給的是原則**：**高風險場景下 agent 負責「提議」，人類負責「決定」；任何涉及生產系統的操作一律走審批門控。** 並強調：**「這不是模型不夠好時的臨時妥協，而是正確的永久架構」**——就像設計良好的自駕車有明確的運行域，而不是擁有無限權限。
  - **同篇還翻轉了「慢＝安全」的直覺**：**「在安全攸關的系統中，反饋回路的速度本身就是一種安全機制。」** 驗證要幾週 → 只能在里程碑測、問題積累很久才爆；驗證只要幾分鐘 → 每次變更都測、問題早暴露、修復成本低。**「那種看起來慢條斯理、小心翼翼的流程，往往恰恰是缺陷悄悄積累了好幾個月、直到某次事故才被發現的流程。」**
  - **IndyDevDan 補的是隔離層**：與其給 agent「你電腦的一個小角落」，不如給它**整台電腦**（agent sandbox）。三個好處：隔離、規模、自主。金句：**「blast radius 就是那個盒子。」** 金鑰問題他用 OpenRouter 的 provisioned key 解（限額 $50、拆掉 sandbox 時一併殺 key）。
- **→ 可立刻落地的一條**（承接你 8/13 已寫下的）：把 **「API 逐端點授權檢查（含 cancel／delete）」** 從一條 checklist 升級成一份**兩層交付規格**——①**分類層**：每個端點標「低風險自動／高風險提議＋人類決定」；②**稽核層**：高風險動作留 transcript ＋ tool call 紀錄供事後追。這兩層正是 OpenAI 與 a16z 各自獨立收斂到的同一個形狀。
- 🔗 [OpenAI · Codex, Behind the Harness（auto review 段在後半）](https://www.youtube.com/watch?v=shRR1e2HXMk)｜[Best Partners TV · a16z 護城河（安全與速度段）](https://www.youtube.com/watch?v=WhIHQNw5GZU)｜[IndyDevDan · Agent Sandboxes](https://www.youtube.com/watch?v=SEI_qIW4o2c)
- ⏱ **值不值得看完**：如果這條真要變服務品項——**Codex 那支值得完整看一次並做筆記**（20 分鐘、資訊密度極高、且 harness 開源可對照原始碼）。

## 🟢 工具用法（單則精選）

### 1. Claude「降智」其實多半是**表達方式對不上**——用 output style 五分鐘解決 ⚡

- **🏢🧠 為什麼是精選**：這支解決了一個你**每天都在付出、但沒被命名的成本**。Gary Chen 舉的實例——他問 Opus 5 怎麼做一個功能，回他「這個設計的正交性保證了狀態收斂的冪等路徑，語意層的抽象已經內化在 pipeline 的攝取階段」。他點出關鍵：**Matt Pocock 與那篇工程師圈瘋傳的部落格，抱怨的全都是「看不懂」，沒有人說它做錯了、測試照樣過**。→ **這是溝通問題，不是模型變笨。**
- **可立刻做的（3 步、30 秒）**：把風格文字貼給 Claude Code 說「幫我加進 output style」→ `/config` → 選 output style。**Claude Code 內建四套**：`Default`（簡潔）、`Proactive`（廢話少、能動手就動手）、`Learning`（故意留一段 code 讓你親手寫）、`Explanatory`（每個改動順便解釋架構與 pattern）。**建議：`Explanatory` 只用在接手別人的 code／新框架／不熟的 repo；熟的專案千萬別開**（本來想解決囉嗦、結果更囉嗦）。
- **自製法（很聰明，值得抄）**：下次收到天書輸出時，先按 `/branch` 從當前對話分岔（不打斷工作）→ 說「請把這段回覆用五種不同風格重寫一次」→ 選你讀起來最不費力的 → 「把這個風格做成 output style」。
- **最有跨域價值的一段**：他從中挖到 **STE100（Simplified Technical English）**——歐洲航太業幾十年前訂的寫作標準（飛機維修手冊寫得看不懂，維修員做錯一步會出人命）：**句子要短、一句只講一個動作、詞彙表固定、一個詞只有一個意思**。**「技術文件寫到沒人看得懂，不是 AI 時代才有的問題，工程界幾十年前就付過代價、也已經解決過。」** ← 這正是「心法可遷移、招式會過期」的活教材，**8/20 演講的備答素材**。
- **關鍵設計原則**：**光跟 AI 說「講簡單一點」沒用，它只會把長廢話換成短廢話。** 有效的是①把你喜歡的溝通方式**精鍊成原則** ②**叫它用你的詞彙說話**（你專案裡使用者叫 member，就規定不准叫 user）。
- **⚠️ 而這句直接打到你懸著的「review 成本反轉」**：他給工程師那套的設計理由是——**「AI 丟給你一千字，你根本不會讀，只會眼睛掃過去、心裡想說應該沒問題吧，然後按下確認。當輸出縮到幾行，你才會真的每一行都讀進去，才擋得住該擋下來的東西。」**

## 🟡 前沿翻盤 ／ Agent 範式（單則精選）

### 3. 「記憶不能外包」＋「記憶是算力的函數」——本週最貼 thinkr 的一支 🔗

- **🧠 me（直接對應 MEMORY.md 待決「缺汰換機制、持續逼近上限」）**：Shlok Khemani 花一年逆向工程了 ChatGPT／Claude／Gemini／Poke 的記憶系統，給出兩條可以直接拿來當設計準則的結論：
  - **①「記憶不能外包」**：ChatGPT 與 Claude 各自獨立演化出**相反**的架構（ChatGPT 走「事實清單 → 常駐 profile」；Claude V1 反過來完全沒有 profile、只給模型兩個工具去**按關鍵字／按時間搜尋過去對話**），三年後才殊途同歸。他的結論：**沒有一種正確做法；今天所有頂尖消費級產品都有記憶，但沒有一個是外包的——記憶要跟產品一起長。**（→ 你目前「MEMORY.md 動態狀態 ＋ auto-memory 靜態事實 ＋ memsearch 向量對話 ＋ /query 原文」這種自建四分工，方向是對的。）
  - **②「記憶是算力的函數」**：任何常駐 profile 有兩種成本——**維護成本**（多久更新一次 × 每次投多少算力）與**服務成本**（profile 有多長 × 每次對話都要帶）。**ChatGPT：4,000 tokens／每幾天更新一次**（高服務、低維護）；**Claude：1,000 tokens／每 24 小時更新**（正好相反）。→ **這就是 MEMORY.md 缺的那把尺**：不是「該不該汰換」，是「你要把預算放在『帶著它』還是『重寫它』」。
  - **③ 天花板不是架構，是 context**：他的 profile 到今天還寫著他去過土耳其（其實沒去，那是他跟 ChatGPT 討論「去泰國還是土耳其」留下的痕跡；真正的決定是跟伴侶當面做的，機票旅館訂單在 email 裡）。他真正生氣的點：**「ChatGPT 甚至不知道這裡有衝突。它對填補自己認知裡的洞不好奇。這不是技術問題，是產品問題。」**
- ｜AI Engineer（核心⭐）｜[影片](https://www.youtube.com/watch?v=5ZGyKWjQDr0)｜🔗 建議 /ingest
- ⏱ **值得看完，14 分鐘**。前半是三年演進史（可快轉），**後半「三個教訓」是精華**。

### 4. 風向轉了：Codex 上、Claude 下——但 Anthropic 在「交付物」上仍明顯領先 ⚠️

- **🏢 對技術棧下注的實際影響**：Riley Brown 匯整的社群共識是「**從 Claude 倒向 Codex**」，理由不是模型分數而是**harness 更好、桌面版好很多、定價更好、拒答更少、訂閱可自由用在其他工具上**（Anthropic 對訂閱跨工具使用限制較多）。他自己的診斷很值得記：**Anthropic 的問題是產品線爆炸與命名混亂**（Co-work 手機端叫 Dispatch、Claude Code 手機端叫 Claude Remote；Fable 轉成只走 API 變得很貴；Claude Design 明明是好產品卻被埋掉）。

## 🔵 商業需求 ／ AI 教育（單則精選）

### 6. 吳恩達：買授權買不到競爭優勢——以及「別被單一供應商鎖定」 🏛️

- **🏢 ctkpro（本週最能直接變成提案語言的一支）**：
  - **開場那句就是 ctkpro 的賣點**：**「沒有哪家公司能僅僅透過購買 ChatGPT 或 Copilot 的授權就獲得競爭優勢。」** 真正的問題不在買了哪個模型，在**找到合適的應用場景 ＋ 人員的變革管理 ＋ 基礎設施**——是一套系統工程。
  - **技術棧原則（可直接寫進提案）**：**「我無法預測一年、甚至六個月後哪個模型會是最頂尖的。所以在構建業務時，最重要的事情之一就是保持選擇的靈活性、不要被單一供應商綁定。」** 他自己同時用 OpenAI／Claude／Gemini。→ 這條比「我們用最強的模型」更有說服力，也更誠實。
  - **價值在應用層不在基建層**：**「當年網路興起時思科賺得盆滿缽滿，但建立在網路之上的那些應用創造的價值要龐大得多。」** 他在 AI Fund 花大量時間幫大企業找的是**能帶來顛覆性自動化的場景**，不是「跟聊天機器人聊聊天、複製貼上、改改 email 語法」。
  - **摩根士丹利案例（可直接抄成服務形態）**：CEO 從最高層定調全面擁抱 AI ＋ **全球每位員工提供 AI 培訓** ＋ 推行**「挑戰實驗室」把業務負責人和技術負責人聚在一起共同探索應用場景**。他的觀察：**業務與技術領導者的這種合作，往往才挖得出真正有價值的場景。**
  - **標準要拉高**：「當你深入思考企業如何創造價值時，你不會滿足於讓某項任務的執行成本降低百分之幾。你會想的是——**怎麼把這項服務規模擴大一百倍**，或**把速度提升十倍**。」
- **另一個順帶的訊號**：他和 Rohan Prasad 在做一個**開源免費的桌面 AI Agent「OpenWorker」**（可在自己電腦上跑，能直接產排版完整的文件、發 email、發 Slack、搭 dashboard，而不是丟一堆文字給你自己排）。
- ｜Best Partners TV（核心⭐）｜[影片](https://www.youtube.com/watch?v=LHCqSqneZGQ)｜🏛️
- ⏱ **值得看完，20 分鐘**。中段的開源／蒸餾論戰可略過（離定標），**「企業落地」與「護城河」兩段是精華**。

### 7. 「學了那麼多 AI，為什麼還是沒加薪？」——本週最貼你 8/20 主軸的一支 🏛️🔗

- **🧠 me ＋ 👨‍👩‍👧 family（本期最強的單則）**：這支等於是**「別人學招式、我練心法」的另一個獨立、有數據支撐的版本**。
  - **那個會被記住的數字**：丹麥兩位經濟學家追蹤約 **25,000 名工作者**，發現 AI 確實省下了時間，**但這些多出來的時間約 85% 又被拿去處理原本工作裡的其他雜事**。→ **「省下時間」在公司眼裡通常只等於「你可以做更多事」。**
  - **另一份研究（5,000 名客服）**：導入 AI 後**進步最多的反而是原本表現較弱的新手**——AI 把高手的經驗打包，讓新手瞬間開外掛追上。→ **「執行與產出」這一段變得極度廉價**；把職涯押在「我做事比別人快十倍」是**完全沒有護城河**的。
  - **核心結論（與 Gary 用了完全不同的路徑得出，卻和 a16z 那條公式同構）**：**稀缺性已經往流程的最前端與最後端移動**——**前端＝高品質的判斷力**（當任何人都能叫 AI 一秒吐出十個企劃，價值就轉移到「選」：誰能過濾掉瞎掰的雜訊、挑出真正可行的方向）；**後端＝扛責任與信任**（「幫忙出主意已經不值錢了，真正值錢的是『我幫你想，而且中間出錯我承擔、我來修』」）。金句：**「別人可以偷走你寫的 skill，但他沒辦法複製你過去兩年幫公司踩過坑並解決問題的信譽。」**
  - **可以立刻換掉的一個問句**：別再問「我還有哪件工作可以交給 AI？」（會掉進盯著待辦清單的迴圈，變成效率很高但沒創造新價值的打工仔），改問「**公司現在最頭痛、卻一直解決不了的問題是什麼？我能不能用 AI 搞定它？**」四個找問題的地方：①哪件事正在浪費公司的錢 ②哪個流程一直讓客戶或同事等 ③哪種錯誤每個月都在重複發生 ④哪個重要決策因為資料太亂、整理太慢而遲遲做不了。**先寫下你希望改變的結果，再決定用什麼工具——順序非常重要。**
  - **證據的三種形態（可直接用在客戶提案，不只用在談薪）**：不要「苦勞紀錄」（用了多少工具、寫了幾百個 prompt）；要**無法造假的證據**：①商業數字的改變（時間／成本／錯誤率前後差多少）②實際的影響力（多少其他部門的人真的在用）③你扛下的責任（只丟點子，還是連後續維護與品質都一併扛）。
  - 後半段用 **Nash Bargaining** 把加薪拆成「你的退路 ＋ 議價權分到的合作剩餘」，四條施力點：推高自己的退路／把餅做大／提高公司失去你的代價／提高議價權。**（對 Alfred 本人的用途不是談薪，是「怎麼幫團隊定價自己的價值」與「怎麼跟客戶談你值多少」。）**
- **👨‍👩‍👧 對教育的推論**：如果「執行」變成標配、稀缺性在「判斷」與「扛責」，那小孩該練的就是**在一堆看起來都對的東西裡挑出真正可行的那個**，以及**把一件事扛到底、出錯自己修**。這比「學會用某個 AI 工具」重要一個量級。
- ｜Gary Chen（核心⭐）｜[影片](https://www.youtube.com/watch?v=aZEmxJ9ivzg)｜🏛️ 🔗
- ⏱ **值得看完，18 分鐘**。**8/20 演講的備答彈藥庫**——「85% 被吃掉」「新手進步最多」「稀缺性往兩端移動」三段可以直接口述。**⚠️ 但大綱已定稿，別為了塞它去動架構。**
