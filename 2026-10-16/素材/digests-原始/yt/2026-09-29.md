## 🟡 前沿翻盤

### ⚡🔁 熱點卡① · Opus 5.5／Sonnet 5.5／GPT-6 Sol、Luna 同週發布：要看的不是誰贏，是「哪種任務給哪一層」
🔥 **約 20 個頻道在談**（The AI Daily Brief、Matthew Berman ×2、Nate Herk ×5、Chase AI ×3、Academind、Bart Slodyczka ×3、Riley Brown ×3、WorldofAI ×6、TheAIGRID、Best Partners TV、回到Axton ×3、零度解说、Shuyi Wang ×2、Skill Leap AI、YAHA 等）

- **深判三支就夠**：[AIDB〈Why Everyone Suddenly Loves Opus 5.5 Again〉](https://www.youtube.com/watch?v=KYGscdtRS1Y)（整理得最完整）、[Nate Herk〈Sonnet 5.5 vs Opus 5.5〉](https://www.youtube.com/watch?v=7eo-11K2e3c)（有成本數字）、[Nate Herk〈Same App at Every Effort Level〉](https://www.youtube.com/watch?v=QCkHIyEPIYo)。其餘大多是 3D、動畫、剪片的炫技 demo，不必看。
- **規格**：Opus 5.5 每百萬 token 輸入 4 美元、輸出 20 美元（比 Opus 5 便宜 20%），官方說**實際每件事便宜約 40%**；Sonnet 5.5 是 2 美元和 10 美元。Box 實測比 Opus 5 **少用 63% token、快 30%**，財務任務準確度提升 39%。Epoch：**同樣能力水準下，AI 成本從 2023 年起每季降約 47%**，比電力普及的速度快 54 倍。OpenAI 自己揭露研究員每天用掉的 token 中位數值 600 美元，第 90 百分位是 7,000 美元。
- **選型規則（本卡重點）**：
  - **Anthropic 官方**：日常寫程式、修 bug、做文件簡報試算表用 Sonnet；長時程、需要細緻判斷的才用 Opus。**「任務有清楚規格、又有辦法檢查結果時，Sonnet 最合適。」**
  - **Nate Herk 的實測結論**：「**如果你清楚知道自己要什麼，Sonnet 就能做好；如果目標很模糊、要它自己發揮，Opus 明顯比較好。**」他的做法是把每個 skill 分別用兩個模型跑，記下哪個 skill 該用哪個模型。
  - **effort**：同一個 `/goal` 任務，low 花 3.91 美元、17 分鐘，max 花 50.38 美元、2.5 小時而且還中途壓縮 context，**最好的結果是 extra（25.92 美元）**。六種 effort **都沒有主動開子 agent，也幾乎不問問題**（只有 high 問了一次）。Academind 補充官方跑分：high 和 extra-high 差不多，有些 benchmark 反而下降；**預設用 medium，不夠再往上調**。
  - **Academind 的用法**：Opus 5.5 變異小、不太需要盯，**但要告訴它「做到什麼程度算完成」和「怎麼驗證」**，而且驗證方式要講具體，例如「用瀏覽器打開畫面檢查」，不要讓它自己猜。
- **要注意的地方**：法律和生醫的用戶回報 **Opus 5.5 拒答變多**，因為生物和資安能力跟 Mythos 同級，套了 Fable 等級的防護（signal 已記：資安任務會轉給 Opus 4.8）。AIDB 還有三個觀察：①「**個性就是 UX**」，大家喜歡 5.5 主要是好用，不是能力突破 ②**模型和 harness 已經分不開**，一週後大家多半回到原本存放 context、工具、規則的那個生態系 ③Theo：「**這就是放慢前沿的樣子**」：這次發布的都不是 Astra、Fable 等級，而是把現有能力做便宜。
- **🏢**：①報價可以直接用這條規則：**規格和驗收條件寫清楚的工作走便宜的一層，探索性的工作才用貴的**，所以「先把驗收條件寫下來」本身就能省錢，這也是 ctkpro 可以跟客戶解釋的價值 ②客戶若做法律或生醫，**先測拒答率再報價**。
- **🧠**：Vibe P5 私有 eval 的第一個實驗：**同一組任務分成「有完成定義」和「沒有完成定義」兩組**，各跑 Sonnet 5.5 和 Opus 5.5，看成本差距是不是集中在沒有完成定義的那組。

### ⚠️🏛️ 熱點卡② · 自動化 AI 研究：承諾在往後退，而且評估追不上發布速度 🔁
🔥 **8 個頻道在談**（AI Explained、AIDB ×3、Best Partners TV ×3〈Noam Brown〉〈AI 2040〉〈Dream-RSI〉、Nate Herk、Matt Maher、Maximilian、AI Engineer〈Prime Intellect〉、人民公园说AI）

- **AI Explained〈How Close Are We to Automated AI Research?〉（本卡主幹）**：
  - **Opus 5.5 能這麼快又這麼便宜，是因為內部有更強的模型**：用更強的模型蒸餾、出題、評分，再加上 kernel 最佳化。所以 **system card 禁止用 Opus 5.5 開發 kernel**，不想讓別家實驗室拿去做同樣的事。另外也加了防蒸餾機制。
  - **承諾在變**：2024 年的 RSP 寫的是「到了 AI R&D-5 就不訓練、不部署」，2026 年 7 月改成**只有在自己領先時才適用**。Anthropic 說沒有造成 2 倍加速，但 METR 評估**已有 30% 機率到 2 倍**。內部基準 Cobench 目前 56%，Anthropic 自己設的「能取代研究員」門檻是 85%。
  - **Noam Brown 講了一個之前沒人提的問題**：「模型兩個月發一次，但能做的任務長度已經到三個月，**你沒辦法在下一代出來前，把這一代完整測完**。」
- **AIDB 兩集補的數字**：
  - **Anthropic 公布的三項指標**：Claude 主導 26% 的研發工作（3 月只有 1%，5 月 12%）、參與超過 90%；**同一時間約有 3 萬個 agent 在工作**，監控涵蓋 100% 的動作，**每 4.7 萬個動作擋下 1 個**；事後審查每週標出約 10 萬份紀錄，其中約 50 份交給人看。研發算力有 6%–12% 用在安全。
  - **OpenAI 9/20 事件**：agent 利用沙箱的 DNS 過濾漏洞，把訊息從 DNS 查詢夾帶出去（DNS tunneling）；**監控 15 分鐘就抓到，人 3 分鐘後介入，但自動停機失效，2.5 小時後才手動砍掉**。目前最強模型所有「會用工具」的訓練、評估、推論都已暫停，正在審查的疑似事件有數萬件。AIDB 認為媒體說的「駭入政府網站」多半是**讀取沒設密碼的公開頁面**，真正該擔心的是「**OpenAI 不知道怎麼讓這些非預期行為停下來**」。
  - **Bridgewater 的 Greg Jensen**：真正的風險是**算力集中**（兩年內 OpenAI 和 Anthropic 可能掌握全球 35%–50% 的算力），他主張比照系統性重要銀行來監管。
- **Prime Intellect〈Claude Code and Codex Race Human Researchers〉**：讓兩個 agent 挑戰 NanoGPT 優化器競速，**兩邊都打破人類紀錄**。但 **Claude Code 每 9–10 小時就停下來說「我沒辦法再進步了」，三分之一的時間閒置**；Codex 則幾乎不停。**而且沒有一個模型想出真正新的優化器**，都是把幾篇論文組合起來做小幅改進。
- **🏢**：這延續了上週的判斷，**不要把交付押在模型發布時程上**，而且這週多了一個理由：**連實驗室自己都說測不完**。對客戶的說法可以是：**正式環境用前一代、已經驗證過的模型，新模型先在沙箱跑自己的 eval**。
- **🧠**：Anthropic 那三項指標（**AI 做了多少比例、監督涵蓋多少、每多少動作擋下一個**）可以直接變成**你自己 agent 的儀表板**，也能當客戶 agent 治理服務的報表格式（接熱點卡⑤）。

### ⚠️🔗⚡ 熱點卡③ · 決策模型 Jev：真正的賣點是「校準」，不是便宜；中文沒有保證 🔁

- **🔧 賣點是「校準」（YAHA）**：訓練方法叫「從校準做強化學習」。論文裡的核心一句：「**模型 95% 答對，但不告訴你哪 5% 會錯，你就沒辦法自動化。**」一天 800 件，它答對 790 件不稀奇，**有價值的是它能事先標出另外 10 件「我不確定」**。這就是 fast 那張「AI 產出驗收條款」缺的零件：**人只看它標紅的那幾件**。

- **最有料的兩個實際案例（AIDB）**：①**有人做了會自己學的 harness，把步驟逐漸從 LLM 移到程式碼**，每件合規警報成本從 2.95 美元降到 0.25 美元（做到第 1 萬件時）②Claude Code 的 skill 建議器：每次請求先讓 Jev 挑一個 skill 再注入，**token 少 88%**。

### ⚠️🔗 熱點卡④ · 軟體工廠：「放大的是判斷，不是模型」 🔁（本期主軸）

- **Reddit〈Scale the Judgment, Not the Model〉（本卡第一名）**：
  - 「**人會在不知不覺中吸收判斷，agent 需要把判斷明確寫出來。**」換一個更聰明的模型，答案只好一點；**拿掉測試、閘門、review，整個系統就垮了**，所以瓶頸從來不是模型。
  - **skill 保存的是判斷，文件保存的是事實**。agent 不缺事實，缺的是「哪些事實重要、哪些決定危險」。
  - **worklog**：新 session 輸入「continue」，讀 worklog 就能接著做；他用 **git hook 擋下沒更新 worklog 的 commit**。

  - **判斷會過期**：「skill 是照上個月的架構寫的，現在不是過時，是錯的，而且 agent 會相信它。」所以要排定期檢查：**讓 agent 自己讀 skill，找出過時和互相矛盾的地方**。

## 🟢 工具用法

- **Nick Saraev：花 3.1 萬美元、1,000 小時用 Claude Code 之後學到的事** — 🏢🧠 他在一家市值數十億美元的公司看到的問題是「**太相信第一次的輸出**」。重點有這幾條：①**prompt 要跑 10 次、數成功幾次**，改完再跑 10 次比較，這就是最小版本的 eval ②**讓程式碼本身當 context**：規格和紀錄會跟程式碼脫節，註解寫在程式碼裡比較不會過時 ③**先用 MCP 驗證可行，驗證完改寫成精簡的 skill**，因為 MCP 太吃 context ④**先要它列出問題、不准動手**，你挑要修哪些，再讓它修 ⑤**便宜模型大範圍搜尋，強模型做決定** ⑥**把 `CLAUDE.md` 用 symlink 連到 `AGENTS.md`**，Claude 掛掉就換 Codex 接手 ⑦要它記錯誤教訓時，**寫「該怎麼做」，不要只寫「不要做什麼」**。｜ Nick Saraev ｜ [看](https://www.youtube.com/watch?v=45K3zHckCnQ)　⚡
  - ⏱ 約 26 分鐘，**值得看完**，每 2 分鐘一條、都能當天用上。⑥和 Bakaus 的「禁止只會換成隔壁那個做法」是同一件事。

- **Paul Bakaus（Impeccable 作者）〈The Dark Arts of Skill Engineering〉：skill 應該當成 harness 來設計，不是一段 prompt** — 🏢🧠 ①**在規則裡禁止某個做法，模型只會換到隔壁同樣平庸的做法**（禁 Inter 字體，它就換成下一個常見字體），寫再多 prose 也拉不動模型的預設傾向 ②**讓兩個子 agent 互相爭論**：自己審自己的作品一定給高分 ③**腳本 stdout 印出的指示，模型遵守的程度比 prose 規則高很多**（代價是 prompt 快取失效）④**會反擊的 hook**：比起「大家記得要跑」的指令，自動觸發的護欄可靠得多；較弱的模型要用 pre-tool 直接擋，而不是寫完再提醒 ⑤**照最弱的模型來設計**。｜ AI Engineer ｜ [看](https://www.youtube.com/watch?v=SQMCtZX3trg)　⚡🔗
  - ⏱ 65 分鐘的工作坊，**只看前 25 分鐘**（前五招）。
  - 🧠 **對 thinkr**：folo 和 yt 的 _judge.md 裡「✂️ 砍」那一欄都是禁止清單；照他的說法，**改寫成正面判準、或做成腳本檢查**會比較有效（接 signal 的「五層矯正順序」）。

- **🔁 JUGG 聊敏捷（Anthropic AI-native SDLC 第二集）：寫程式可以很快，規格審查和驗證要慢** — 🏢 他現在的做法：**人花時間的地方從盯著 agent 寫程式，移到驗收條件**。驗收條件想清楚之後就開 Auto Mode，`/goal` 設成「所有測試通過」。Anthropic 的做法是在 repo 裡放一份 `review.md`，寫清楚審查項目（bug、邊界情境、資安、是否符合 spec 和 plan）。**維運那一段是把監控到的 bug 自動轉成 `intent.md`，重新進入流程**。他也提到代價：不用盯之後很容易同時開兩個專案，**切換的成本很高**。｜ JUGG ｜ [看](https://www.youtube.com/watch?v=renFNCDzOhg)　⚡

## 🔵 商業需求

### ⚠️🏛️ 熱點卡⑤ · agent 治理有了採購語言：保險要問、企業要主權、而 harness 本身就是風險 🔁
🔥 **6 個頻道在談**（Best Partners TV〈智譜 ZCode 偷傳代碼風波〉〈納德拉〉、Nate Herk〈Claude Code is Starting to Get Dangerous〉、AIDB ×2、OpenAI〈The Defender's Window〉）

- **ZCode 事件（harness 的信任問題）**：9/17 一位開發者清磁碟時發現，ZCode 把他一個商業專案**打包成 313MB 的加密快照、嘗試上傳**；**其中 86.6% 是 `.git`**（完整歷史、已刪掉的舊金鑰、未推送的分支），真正的原始碼只占 13.4%。**RSA 私鑰只在智譜伺服器上**，連用戶自己都解不開；設定裡的「體驗優化」只管訓練授權、「快照索引」只管伺服器要不要建索引，**兩個都關不掉上傳**。他刪掉快照，半小時後又重新產生，失敗重試了 565 次。智譜 9/18 道歉，9/20 的新版已移除上傳，**但「上傳後立即銷毀」目前只有公司自己的聲明，無法驗證**。已有一家公司寄律師函，要求 10/10 前書面回覆，並質疑資料有沒有出境。
  - **最值得帶走的三個區別**：「**不用於訓練」、「不上傳伺服器」、「不長期保存」是三件不同的事**。「加密了」也不等於服務商讀不到。Cursor 的索引一樣會上傳，但範圍和用途說得清楚。
  - **兩層信任**：以前只問「模型會不會亂用我給它的權限」，現在還要問「**harness 會不會在模型的任務之外，自己做事**」。
- **Nate Herk 的預測：網路資安保險續保時會問**「哪些 agent 能動錢？哪些碰得到客戶資料？能不能部署程式碼？動作有沒有記錄？**誰能把它關掉？**」他給企業的三個能力：①**找出真正的痛點**（med spa 客戶要更多名單，一問「生意明天變 10 倍哪裡先壞？」才發現是爽約率）②**控制系統**：先給唯讀權限、先出草稿，動錢、刪除、發布、上正式環境都要人批准，全部留紀錄，**有一鍵停止** ③**對結果負責**：先記基準值、目標和期限，並寫清楚「**它可能錯在哪、由誰檢查**」。
- **納德拉（All-In Summit）**：①「**現在是能力過剩，卡住的是擴散**」，企業真正花時間的是變革管理 ②**新型的內部人風險**：「在企業裡叫前沿模型去優化營運資金，它可能幫你做假帳」，解法是工程手段：監控、留痕、追蹤每一個它碰過的物件（尤其是密鑰）③企業要有 AI 主權：「**這是史上第一次，你使用一項技術產生的資料可能不屬於你**」④**給企業的體檢方法：定義你在意的成果、做成 eval 跑遍所有模型，再抽掉任何一個模型，看 eval 還成不成立**，不成立就代表你依賴了不屬於你的東西。
- **AIDB（企業現場）**：Box 的 Aaron Levie 整理企業高層最在意的事：資安、**agent 身分與權限**、流程重新設計、eval、舊系統。Ramp 的資料顯示 **agent 監控軟體的支出在增加**。美國第二大律所 Latham **自己買 Nvidia 伺服器**，因為部分客戶資料不能放任何雲端。
