### P2 · 為什麼是這個順序（先講框架邏輯，讓聽眾有地圖）

- **要點**：用 AI 的能力分三層，**由下往上堆**——
  1. **Prompt（下指令）**：把話講清楚，讓 AI 給對答案。
  2. **Context（餵背景）**：不只下指令，還把「AI 該知道的背景」餵給它。
  3. **Harness（搭系統）**：不只餵背景，還搭一整套「AI 自己會跑」的工作流。
- **為什麼由下往上講**（三個理由，可放小字）：
  1. **三層是嵌套的**——Harness 裡面跑著 Context、Context 餵給 Prompt。由內往外講最自然。
  2. **符合學習曲線**——所有人都只熟第一層 Prompt，從你最熟的地方接進去，一層層加。
  3. **一張階梯圖**：下面寬（人人都在做）、上面窄（少數人爬到）。
- 🎤「先給你一張地圖。用 AI 有三層：最下面『下指令』，人人都會；中間『餵背景』，開始有差距；最上面『搭系統』，這是護城河。今天我從最下面、你最熟的那層開始，一層一層往上加——每加一層，我只問你一句：**上一層做不到、這一層多了什麼？**」
- 🎨 **這頁是全場的錨**：一張「三階梯」圖（Prompt 在底、Context 中、Harness 頂），後面每一層都回到這張圖點亮一階。

### P3 · 【第一層】Prompt Engineering ——「把話講清楚」

- **是什麼**：把你的需求講清楚，讓 AI 一次給出對的答案。這是**最基礎、也是每個人現在都在做**的事。
- **關鍵動作**：講清楚「角色、任務、格式、限制」——與其問「幫我寫文案」，不如說「你是餐飲業行銷，幫我寫一則 IG 貼文，主打週年慶、200 字內、口吻活潑」。
- **局限（為下一層鋪路）**：
  - **一次性**——這次講清楚了，下次要重講。
  - **AI 不知道你的背景**——它不認得你的公司、你的客戶、你上週做過什麼。你得每次把背景重打一遍。
- 🎤「第一層，人人都在做——打開 ChatGPT 問問題。做得好不好，差在你會不會『把話講清楚』。但它有個天花板：**AI 每次都像新來的員工，你得從頭交代一次背景。** 這很累，對吧？這就帶我們到第二層。」

- 【BNI 案例】：**老闆用 ChatGPT 幫忙寫報價信、想文案、翻譯客戶郵件。** 講得越具體，出來越好用；但你每次都得從頭交代「我們是做什麼的、對象是誰」。
- 【Retro 案例】：**寫一個好的 code 生成指令**——把需求、限制、期望輸出講清楚，讓 AI 一次生對。⚠️ Alfred 補實例：（例如某次一句話 prompt vs 結構化 prompt 的生成品質落差／某同事踩過的「講不清楚 → AI 亂生」的實例）

- **一句記憶點**：🔑 **「Prompt = 把 AI 當成很聰明、但每次都失憶的新員工。」**

---

### P4 · 【第一層 → 第二層】為什麼光靠指令不夠

- **要點**（過渡頁，讓階梯感浮現）：Prompt 再厲害，都有一個共同的痛——
  - **它不認得你的世界。** 你的公司規範、客戶脈絡、專案歷史，它一概不知。
  - 所以你花大量時間在「每次重新解釋背景」，而不是在「解決問題」。
- **本週訊號佐證**（可放小字，非技術版可略）：這週好幾篇不約而同指出一個現象——「**一個人用 AI 翻了十倍，全公司卻沒跟上**」。為什麼跟不上？因為那個超級用戶把「背景」都放在自己腦袋裡，別人接不住。**背景沒被沉澱下來，就無法複製。**
- 🎤「所以第一層的天花板，是『背景每次都要重講』。而當只有一個人會『重講背景』，那間公司就永遠只有一個人快。要突破，就得把『背景』從腦袋裡拿出來，餵給 AI——這就是第二層。」
- 📊 出處：folo 7/19-slow 熱點卡 1（「一人翻十倍、全公司沒跟上」＝採用鴻溝）

### P5 · 【第二層】Context Engineering ——「餵背景」

- **是什麼**：不只下指令，還把「AI 該知道的背景」**事先準備好、餵給它**——公司規範、客戶脈絡、專案歷史、常見問答。
- **比第一層多了什麼**：**AI 開始「懂你的世界」**。它不再是失憶的新員工，而是「看過你公司手冊、記得專案歷史」的老員工。
- **關鍵動作**：把散在腦袋和聊天記錄裡的背景，**整理成 AI 讀得懂的文件**（規範、範例、脈絡），讓 AI 每次都帶著這些背景工作。
- 🎤「第二層，關鍵字是『背景』。與其每次重講，不如**一次把背景整理好、餵給它**。這時 AI 就從『失憶的新人』升級成『讀過公司手冊的老員工』。它開始懂你的世界——你的規矩、你的客戶、你做過的事。」

- 【BNI 案例】：**把公司的 SOP、常見問答、產品資料餵給 AI，做成一個客服助手。** 客人問什麼，它照你公司的規矩答，不是照網路上的通則答。你不用每次教它「我們家退貨政策是什麼」——它已經知道。
- 【Retro 案例】：**CLAUDE.md（專案規範）／客戶專案脈絡文件／記憶系統（thinkr）。** 讓 AI 每次進來就帶著「這個專案的規則、歷史、慣例」。⚠️ Alfred 補實例：（例如 ctkpro 某客戶專案的 context 文件怎麼組、或 thinkr 的 `_index.md` + 交叉連結怎麼當 AI 的記憶／某次「有 context vs 沒 context」的產出落差）
- **本週前沿連結（可加深，非技術版略）**：這層正在被「工程化」——**Agent Memory / LLM Wiki 已是連續第六期的熱門主題**，社群開始推「開放記憶標準（OKF）」，把「文件變成 AI 可靠讀的基建」。意思是：**「餵背景」正從手工藝變成一門正式工程。**（folo 7/23-signal 熱點卡 3）

- **一句記憶點**：🔑 **「Context = 把 AI 從『失憶新人』養成『讀過公司手冊的老員工』。」**

---

### P6 · 【第二層 → 第三層】為什麼「餵好背景」還不是終點

- **要點**（過渡頁）：就算 AI 懂你的世界了，它還是**在等你下每一個指令**——
  - 你問一句、它答一句；你不問，它不動。
  - 真正省力的，是讓 AI **不用你盯著、自己把一整串流程跑完**。
- 🎤「第二層很強了——AI 懂你的世界。但它還是被動的：你按一下、它動一下。想像一下，如果有一件重複的事，AI 能**自己觸發、自己跑完好幾步、自己檢查對不對，只在關鍵時刻回來問你一句**——那才是真正的省力。這就是第三層，也是差距真正拉開的地方。」

---

### P7 · 【第三層】Harness Engineering ——「搭系統」

- **是什麼**：最上層——不只餵背景，還搭一整套「**AI 自己會跑的系統**」：會被觸發、會走多個步驟、會自我檢查、會迴圈修正。人只守在關鍵決策點。
- **比第二層多了什麼**：**AI 從「被動回答」變成「主動成系統地運轉」**。人退到頭尾兩個位置——**把問題定義清楚（頭）、把結果驗收好（尾）**，中間交給系統。
- **關鍵零件**（Retro 版可展開、BNI 版帶過）：
  - **目標與邊界**（agent 可自決 vs 要回來問人的界線）
  - **標準步驟（SOP）＋ 自我驗證（附證據給人審）**
  - **迴圈**（每輪學到的記下來，不重犯同樣的錯）
- 🎤「第三層，關鍵字是『系統』。到這裡，AI 不再是等你問的工具，而是一個**會自己跑的流程**：它被觸發、走完多步、自己檢查、有問題自己修，只在真正需要決策時回來找你。你的角色也變了——你不再是『打字下指令的人』，你是『定義問題 + 驗收成果的人』。」

- 【BNI 案例】：**一個「自動處理進單」的 agent 流程**——客人下單，AI 自動：回覆確認信 → 記進系統 → 通知出貨 → 有異常才回報給你。你不用一封一封處理，只在「異常」時才出手。從「你操作工具」變成「系統替你運轉」。
- 【Retro 案例】：**loop contract（goal / boundaries / SOP / verifier）、開發者退成 PM + QA、autoreview／規格先行／Brownfield 五步。** AI 執行、人守決策點與 code review。⚠️ Alfred 補實例：（例如 ctkpro 已在跑或想跑的某個 agent 工作流／某條 loop contract 的實際樣子／某次「人退成 PM+QA」的真實交辦）
- **本週前沿連結（Retro 版可深講）**：
  - **開發者被重塑成 PM + QA**——寫代碼下放給 agent，人只做「定義問題 + 驗收」（yt 7/24 Agent 範式熱點卡）。
  - **Loop → Graph → Harness Engineering**——AI coding 正從「閉眼 yolo」走向「工程紀律」（Chase AI / Dex Horthy，yt 7/24）。
  - **「own your intelligence」＝護城河在 harness**——Harrison Chase：真正的長期優勢不是模型（模型會被租、會被換），是「你擁有整條 agent 開發生命週期 + 那個複利的 feedback loop」（folo 7/23-signal 熱點卡 2）。

- **一句記憶點**：🔑 **「Harness = 你不再操作 AI，你設計一個『AI 自己會跑』的系統，然後只守決策點。」**

### P8 · 一張圖總覽三層（回到 P2 的階梯，全部點亮）

- **要點**：把三層並排，用同一組維度對比——

| | **① Prompt 下指令** | **② Context 餵背景** | **③ Harness 搭系統** |
|---|---|---|---|
| **一句話** | 把話講清楚 | 讓 AI 懂你的世界 | 讓 AI 自己會跑 |
| **AI 像** | 失憶的新員工 | 讀過手冊的老員工 | 一條會自轉的產線 |
| **你的角色** | 打字下指令 | 準備背景、下指令 | 定義問題 + 驗收 |
| **多了什麼** | — | 背景、記憶 | 自動、多步、自我檢查、迴圈 |
| **誰在這層** | 幾乎所有人 | 少數人 | 極少數人（= 護城河） |

- 🎤「一張圖收尾三層——往右一格，AI 就更聰明地替你工作一分、你就更省力一分。左邊人擠人，右邊沒幾個人。**競爭力，就藏在你願不願意往右爬。**」
- 🎨 這頁是「金句圖」——建議做成一頁大表格 / 三階梯上色，當全場記憶錨點與拍照頁。

### P9 · 這是一座「往上爬的階梯」（收尾主論點）

- **要點**：
  - 三層不是「三選一」，是**疊上去的**——上層一定包含下層。
  - **多數人卡在第一層**（一直在下指令、一直在重講背景）。
  - **真正的競爭力，在爬到第三層**（把會的事變成系統，讓它自己跑）。
  - 好消息：**每個人都已經站在第一層了**，往上爬是「加一層」，不是「從零學」。
- 🎤「所以今天的重點就一句話：這是一座**階梯**，不是三個選項。你已經站在第一階了。問題只有一個——**你要停在這，還是往上爬？** 每往上一階，AI 替你做的就多一分，你要親手做的就少一分。」

- **一句記憶點**：🔑 **「別問 AI 夠不夠強，問你自己（你的公司）站在第幾階。」**

### P11 · （備用頁）三層各自的「上手第一步」

> 若時間夠 / 聽眾想要「明天能做什麼」，加這頁把階梯變行動。

- **在第一層想上手**：下指令時多給「角色 + 任務 + 格式 + 限制」四件事。
- **想爬到第二層**：挑一件你「每次都要重講背景」的事，把背景寫成一份文件餵給 AI（公司 SOP / 常見問答 / 專案規範）。
- **想爬到第三層**：挑一個「重複、步驟固定」的流程，設計成「AI 觸發 → 多步執行 → 自我檢查 → 異常才回報」。
- 🎤「不用一次爬三層。挑你最有感的一件事，往上加一層就好。」

### P13 · （通用備用頁）常見誤解澄清

> 預防聽眾把框架聽歪，可放可略。

- ❌「所以第三層最好，我應該跳過前兩層」→ 不對。**上層包含下層**，你 prompt 講不清，harness 也會跑歪。
- ❌「Harness = 全自動 = 不用人」→ 不對。**最上層反而更需要人**——守在「定義問題」和「驗收」兩個決策點（本週 Dex Horthy 的核心：全自動的「無人工廠」會失敗）。
- ❌「這是工程師才懂的事」→ 不對。三層是**用 AI 的通用能力**，老闆、行銷、客服都適用，只是案例換皮。
- 🎤「最容易聽歪的一點：爬到第三層，不是『不用人了』，是『人退到更重要的位置』——定義問題、把關結果。這兩件事，AI 到現在都還做不了。」
