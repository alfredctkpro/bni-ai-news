## 🟢 工具用法

### 🔥 熱點卡 1 · TL → EM：用 Agent 的角色轉換（🔥 4 則／同一人多角度深化）｜🔗 建議 /ingest
**宝玉今年最大的方法論轉變：從 Tech Lead（事必躬親、盯到程式碼層）變成 Engineering Manager（只定義任務與驗收標準、不看實作細節）。**

- 🏢 **ctkpro**：這是你「架構師之問」（USER.md）的**外部驗證版**——每個任務先問「該我親自做，還是設計系統／交給團隊？」宝玉給出可操作的分界：**EM 只管「任務目標＋怎麼算通過驗收」**。可直接搬進團隊 SOP，也直接回答 P4 卡住的「團隊怎麼交出 Context」——Context 即驗收標準的載體。
- 🧠 **me**：你的「AI 協作者能力前緣」下一步不是學更多 prompt 技巧，是**練「定義驗收標準」的能力**。宝玉配套三招：①`/goal` 用得好的關鍵＝設計嚴格驗收標準，每階段講清「怎麼算通過」才不跑偏 ②不再用 Hook 自動 commit（hook 任何任務結束都觸發、太笨），改讓 Agent 自己判斷該不該 commit ③在 `AGENTS.md`/`CLAUDE.md` 寫死「每個改檔任務必須以 git commit 收尾」。
- **多方觀點**：宝玉（實踐者，寫成完整部落格文）｜swyx 同期呼應「main chat vs /side chat ＝ doing the work vs doing metawork」，是同一套「分層授權」思路的另一面。
- 🔗 [宝玉部落格·完整版](https://baoyu.io/blog/coding-agent-em-shift)｜[TL→EM 推文](https://x.com/dotey/status/2082557559177941304)｜[/goal 驗收標準](https://x.com/dotey/status/2084420331574284580)｜[不用 Hook 的理由](https://x.com/dotey/status/2082558900876779987)｜[AGENTS.md commit 規則](https://x.com/dotey/status/2082505782440902700)

### 🔥 熱點卡 2 · 多模型分工成為主流工作流（🔥 4 人在談：宝玉／歸藏／swyx／小互）
**「一個 session 裡用不同模型的 subagent」從技巧變成標配做法。**

- 🏢 **ctkpro**：直接降接案成本——貴模型只用在該用的地方。宝玉的具體配方：**Fable 5 寫技術方案文件（可批註、其他 Agent 好接手）→ Codex 執行 → Fable 5 驗收**，兼顧品質與性價比。歸藏示範一句 prompt 調三模型（Grok 爬取／Kimi 生成網頁／另一個統整）。
- 🧠 **me**：實作入口就在你手上——**主 agent 開 subagent 時可指定 subagent 模型**（宝玉明講）。你的 thinkr agent 群（folo-digest／yt-digest／圓桌）都可以照這條調校成本。
- 另附宝玉的推理強度配置實測：GPT-5.6 Sol 預設 `xhigh`（不會過度推理）、Fable 5 用 `high`／多數時候 `medium`——**更高推理強度不見得更聰明，但一定更慢更費 token**。
- 🔗 [宝玉·三段式配方](https://x.com/dotey/status/2084361778377404715)｜[subagent 指定模型](https://x.com/dotey/status/2084424032762384846)｜[歸藏·一句 prompt 調三模型](https://x.com/op7418/status/2082315101080879424)｜[推理強度配置](https://x.com/dotey/status/2082280325040750998)

### 🔥 熱點卡 3 · MCP 2.0（2026-07-28 規範）：從有狀態改成無狀態（🔥 3 則）
**MCP 社群呼聲最高的改動落地：廢掉握手與 session ID，MCP server 終於能上雲、可 serverless、可水平擴容。**

- 🏢 **ctkpro**：這是**技術棧決策點**。舊 MCP 因為「客戶端得回到同一台機器」而無法擴容，等於不能做正式服務；新規範讓 **MCP server 變成一般無狀態 API**，你若要幫客戶（診所數位化／建站）做 AI 整合，MCP 現在才真的可以進生產環境。
